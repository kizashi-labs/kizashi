### 除去パターンと対応方針
- `USE_MOCK ? MOCK_X : []` → `[]` または型付き空配列 `[] as TypeX[]`
- `m(MOCK_X)` → `[]` or `{} as TypeX`（`m()` はモック型ラッパー関数）
- `...(USE_MOCK ? { initialData: MOCK_X } : {})` スプレッド → 完全削除
- `if (USE_MOCK) return MOCK_X` ブランチ → 削除
- `EMPTY_*` がモックセクション内にあった場合 → コンポーネント関数内に再定義
- `generatePoints` / `generateMockHourly` / `generateMockSecret` など「モック」という名前でも実UIで使う関数は保持
- `ROLE_COLORS`・`MONTHLY_ROI`・`MONTHS`・`BENCHMARK_ROWS` など静的UI定数も保持

### Windows OS版数表示修正

エンドポイント一覧の「OS」列に `Windows` しか表示されなかった問題を修正した。

**根本原因の特定過程**:
1. `server/internal/ingestion/handler.go` のgRPCハートビートハンドラーが `os_version=""` をハードコードしていた
2. gRPC `HeartbeatRequest` protoに `os_version` フィールドが存在しなかった
3. protoの raw descriptor（バイナリ）をprotocなしに完全更新できないため、gRPCメタデータ方式を採用

**実施した修正**:

| ファイル | 変更内容 | コミット |
|--------|---------|---------|
| `agent/cmd/agent/platform_windows.go` | `RtlGetVersion()`（kernel API）でビルド番号・製品種別を取得し正確なWindows版数文字列を生成 | f122ae1 |
| `agent/internal/heartbeat/heartbeat.go` | `osVersion string` → `osVersion func() string`（毎ハートビートで再評価） | f02b962 |
| `agent/cmd/agent/main.go` | `osVersionString()` の呼び出し結果でなく関数参照 `osVersionString` を渡すよう修正 | f02b962 |
| `proto/agent/v1/ingestion.proto` | `HeartbeatRequest` に `string os_version = 10` 追加 | 157dc77 |
| `proto/gen/go/agent/v1/ingestion.pb.go` | `OsVersion` フィールド・`GetOsVersion()` メソッドを手動追加 | 157dc77 |
| `agent/internal/transport/grpc_client.go` | protoリクエストに `OsVersion: req.OSVersion` 追加＋gRPCメタデータ `x-os-version` ヘッダーを送信 | 28e8fa0 |
| `server/internal/ingestion/handler.go` | proto fieldが空の場合、受信メタデータ `x-os-version` からos_versionを読み取るフォールバック追加 | 28e8fa0 |

**技術的補足**:
- protoの raw descriptor（gzip圧縮済みバイナリ）はprotocなしに更新困難なため、gRPCメタデータ方式で迂回。

### ブルートフォース対策の技術詳細

**DB永続ロックへの移行（53f0acc）**

- 既存スキーマの `failed_login_count` / `locked_until` カラムを活用
- `store/users.go` の `Authenticate()` 関数内でロック確認・カウント更新・リセットを実装
- ロック条件: 5回失敗で15分ロック
- 成功時: `failed_login_count=0, locked_until=NULL` にリセット
- インメモリIPリミッタ（`globalLimiter`）は引き続き第一防衛線として残置

**二層構造の仕組み**:
1. `globalLimiter`（インメモリ、IPベース）: 存在しないアカウントへの攻撃も遮断（DB到達前に弾く）
2. DB永続ロック（ユーザーベース）: コンテナ再起動後もロック状態が維持される

**注意事項**: `globalLimiter` はコンテナ再起動でリセットされる。テスト中にロックがかかった場合は `docker restart kizashi-api` で解除可能（DB側は `UPDATE users SET failed_login_count=0, locked_until=NULL` でリセット）。

### 技術詳細

#### JWT_SECRET 弱値検出の改善

`secrets.go` の弱いシークレット拒否リストに以下を追加:
- `change-me`, `change_me` — ハイフン付きの "changeme" 変種を検出
- `in-production`, `in_production` — "本番で変更してください" 系のデフォルト値を検出
- `example` — サンプル設定値を検出

**根本原因**: 既存リストは `changeme`（ハイフンなし）のみだったため、`change-me-in-production-at-least-32-chars`（32文字以上・8種以上の文字）が全チェックをすり抜けていた。

#### CORS 修正箇所

| ファイル | 行 | 修正前 | 修正後 |
|----------|-----|--------|--------|
| `notification/websocket.go` | 69, 125, 224 | `Access-Control-Allow-Origin: *` | ルーターCORSミドルウェアに委譲 |
| `handlers/live_response_handler.go` | 172 | `Access-Control-Allow-Origin: *` | ルーターCORSミドルウェアに委譲 |

CORSポリシーは `ALLOWED_ORIGINS` 環境変数で制御:
- 設定時: 指定オリジンのみ許可（`Vary: Origin` ヘッダー付き）
- 未設定時: `*`（開発環境用フォールバック）
