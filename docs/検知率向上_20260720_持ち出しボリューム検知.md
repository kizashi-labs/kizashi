# 検知率向上 2026-07-20(3) — データ持ち出しボリューム検知（T1048）

## 背景

キルチェーン最終段の**データ持ち出し（exfiltration）は VOLUME 現象**であり、個々の接続を見るルールでは検知できない。各フロー・各パケットは正常に見え、**単一外部宛先への累積送信バイト量**でのみ窃取が露呈する。実際にコードを当たると:

- ネットワークテレメトリには `bytes_sent`/`bytes_recv` が存在（proto: `NetworkEvent.bytes_sent`）。
- しかし `alert_pipeline` はそれを **UEBA の ML 特徴量に入れるだけ**で、**大量送信でアラートを上げる検知器が無い**。
- 既存の関連検知: アーカイブ生成（T1560.001, winrar/7z）は builtin でカバー、C2 ビーコン（`beacon_detector.go`）は高度（ハーモニック折り畳み）にカバー済み。だが**持ち出しの「量」そのもの**は未カバー。

## 実装（`exfil_volume.go`）

`NetworkScanDetector`(T1046) と同型のステートフル検知器を detection エンジンに追加:

- **(agentID, 外部dst) 別**に外向きバイトを窓(10分)内で累積し、単一外部宛先への累積が `exfilMinBytes`(500 MiB)を超えたら **T1048** で発火。
- **内部宛先は除外**: `isExternalIP` が RFC1918 / ループバック / リンクローカル / マルチキャスト / CGNAT(100.64/10) / IPv6 ULA(fc00::/7) を弾く。→ **社内バックアップ・ファイルサーバ転送では鳴らない**（持ち出しは定義上ネットワークの外へ出る）。
- kill-chain に **exfiltration 段**を供給。severity 7（レビュー推奨）。
- `matches` に載るため kill-chain 相関へ自動供給。発火後 dedup、キー数上限で evict。

## 誤検知への配慮

- **外部宛のみ**計数（内部転送を完全除外）。
- **宛先別**累積（多数の宛先へ薄く分散する正常トラフィックは各宛先で閾値未満）。
- 閾値 `exfilMinBytes` / 窓 `exfilWindow` は定数で調整可。クラウドバックアップ等の大容量正常アップロードが FP になる場合は suppression / 閾値で個別調整。severity 7 は「自動遮断」ではなくアナリスト・レビュー向け。

## テスト（`exfil_volume_test.go`）

- `TestIsExternalIP` — 外部/内部(RFC1918・CGNAT・IPv6 ULA 等)/不正文字列の判定。
- `TestExfilVolume_FiresOnLargeUpload` — 累積が閾値超で1件発火・T1048。
- `TestExfilVolume_InternalDestinationIgnored` — 同量でも内部宛は無音。
- `TestExfilVolume_SpreadAcrossHostsNoFire` — 多数宛先へ分散は各宛先閾値未満で無音。
- `TestExfilVolume_WindowExpiry` — 窓外に散る細い転送は累積せず無音。
- `TestHumanBytes` — バイト表示。
- `detection` パッケージ全 green・`go vet` clean。

## 効果

- 持ち出し（exfil）段のリアルタイム検知を新設。シグネチャ・周期性に依存しない**量ベース**の検知で、大容量アップロード型の窃取（HTTPS PUT / クラウドストレージ等）を捕捉。
- kill-chain 相関に exfil 段を供給し、多段侵入の相関検知率も底上げ。
