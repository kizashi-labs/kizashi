## 1. システム要件

### 対応プラットフォーム

| OS | バージョン | アーキテクチャ |
|----|-----------|--------------|
| Linux | Ubuntu 20.04以上 / RHEL 8以上 / Debian 11以上 | x86_64, arm64 |
| macOS | 12 (Monterey) 以上 | x86_64 (Intel), arm64 (Apple Silicon) |
| Windows | 10 / 11 / Server 2019以上 | x86_64, arm64 |

### リソース要件

| リソース | 使用量 |
|---------|-------|
| CPU | 通常時 < 1%（監視強度による） |
| メモリ | < 50MB |
| ディスク | < 100MB（オフラインバッファ含む） |

### 必要な権限

| OS | 必要な権限 |
|----|----------|
| Linux | root（eBPF使用のため） |
| macOS | root（Endpoint Security Framework使用のため） |
| Windows | 管理者（ETW使用のため） |

### ネットワーク要件

| ポート | 用途 | 方向 |
|--------|------|------|
| **8080** | バイナリダウンロード・API（HTTPS/HTTP） | アウトバウンド |
| **9091** | テレメトリ送信（gRPC Ingestion） | アウトバウンド |

- ファイアウォールでエージェントマシンから上記ポートへの **アウトバウンド接続** を許可してください
- 管理UI（ポート3000）へのアクセスはエージェントマシンから不要です

## 3. Linux / macOS へのインストール

### スクリプトによる自動インストール（推奨）

```bash
sudo bash deploy/install/install.sh \
  --server edr.example.com \
  --token 【エンロールメントトークン】
```

スクリプトは以下を自動で行います：

1. OSとアーキテクチャの検出（linux/darwin、amd64/arm64）
2. `edr-agent` と `edr-watchdog` バイナリのダウンロードとSHA-256検証
3. `edr` システムユーザー/グループの作成
4. バイナリのインストール（`/usr/local/bin/`）
5. 設定ファイルの生成（`/etc/edr/agent.toml`）
6. **watchdog** を systemd（Linux）または launchd（macOS）サービスとして登録・起動
   - watchdog が edr-agent を監視・自動再起動します
   - クラッシュ時の自動ロールバック機能あり

### インストール後の確認

**Linux**:
```bash
# サービスの状態確認
sudo systemctl status edr-agent

# ログの確認
sudo journalctl -u edr-agent -f
```

**macOS**:
```bash
# サービスの状態確認
sudo launchctl list | grep edr-agent

# ログの確認
tail -f /var/log/edr-agent/agent.log
```

### インストールディレクトリ構成

```
/usr/local/bin/
├── edr-agent              # エージェントバイナリ
└── edr-watchdog           # ウォッチドッグ（スーパーバイザー）バイナリ

/etc/edr/
├── agent.toml             # 設定ファイル
└── enrollment.token       # エンロールメントトークン（root:edr 640）

/var/log/edr/
└── agent.log              # ログファイル

/var/lib/edr/
├── quarantine/            # 隔離ファイル保存先
└── edr-agent.bak          # 自動更新前のバックアップ（ロールバック用）

# systemd ユニットファイル
/etc/systemd/system/edr-watchdog.service
```

## 4. Windows へのインストール

### スクリプトによる自動インストール（推奨）

**PowerShell（管理者として実行）**:

1. Web UIにログイン → **エージェント配布** ページでインストールコマンドを取得
2. PowerShellに貼り付けて実行

コマンドの形式（エージェント配布ページからコピー）:
```powershell
iwr -useb "http://【サーバーIP】:8080/api/v1/installer/script?os=windows&arch=amd64&token=【トークン】" | iex
```

> **注意**: インストールコマンドのURLは管理UIポート（3000）ではなくAPIポート（**8080**）を使用します。

スクリプトは以下を自動で行います：

1. `C:\Program Files\EDR Agent\` へのバイナリダウンロード
2. `config.toml` 設定ファイルの生成（エージェントID・ホスト名を自動設定）
3. **EDRAgent** Windowsサービスの登録・起動
4. 隔離フォルダ（`C:\ProgramData\EDRAgent\quarantine\`）の作成

### インストール後の確認

```powershell
# サービスの状態確認
Get-Service -Name "EDRAgent"

# サービスの詳細確認
sc.exe query EDRAgent
```

または、**サービス管理ツール**（`services.msc`）で「EDR Platform Agent」を確認します。

Web UIの **エンドポイント** ページにホスト名とステータス「オンライン」が表示されれば成功です。

### インストールディレクトリ構成

```
C:\ProgramData\EDRAgent\
├── bin\
│   └── edr-agent.exe      # エージェントバイナリ
├── config\
│   └── config.toml        # 設定ファイル
└── quarantine\            # 隔離ファイル保存先
```

> **注意**: 実際のパスはインストール方法によって異なる場合があります。
> `sc.exe qc EDRAgent` の `BINARY_PATH_NAME` フィールドで正確なパスを確認してください。

### サービスの手動操作

```powershell
# 状態確認
sc.exe query EDRAgent

# 停止
sc.exe stop EDRAgent

# 起動
sc.exe start EDRAgent

# 再起動
sc.exe stop EDRAgent; sc.exe start EDRAgent
```

### エージェントバイナリの更新

新しいエージェントビルドを既存端末へ反映する手順です。

> **重要:** 更新目的でフルインストーラ（`install.ps1` / `install.sh`）を再実行しないでください。インストーラは実行のたびに**新しい Agent ID を生成して設定を再作成**するため、ダッシュボードに**別エンドポイントとして重複登録**されます。Agent ID を保つにはバイナリのみ差し替えてください。

#### 推奨: 更新スクリプト

`deploy/install/update.ps1`（Windows）/ `update.sh`（Linux・macOS）は、設定・Agent ID を保持したままバイナリのみ差し替えます。SHA-256 検証・冪等（同一バイナリならスキップ）・失敗時の自動ロールバックに加え、後述の**整合性ハッシュサイドカーも自動更新**します。標準インストール（サービス `EDRWatchdog` / `agent.toml`）が対象です。詳細は `deploy/install/README.md` の「Updating an Existing Agent」を参照。

```powershell
# Windows（管理者 PowerShell）— サーバーURLは agent.toml から自動取得
.\update.ps1
```
```bash
# Linux / macOS
sudo ./update.sh
```

#### 手動更新（旧型インストール / スクリプトが使えない場合）

サービス名・パスは端末の実構成に合わせてください（旧型インストールは `EDRAgent` サービス・`config\config.toml` のことがあります。`sc.exe qc EDRAgent` で `BINARY_PATH_NAME` と `--config` を確認）。

```powershell
# Windows 例（差し替え対象とサービス名は実構成に合わせる）
$bin = "C:\ProgramData\EDRAgent\bin\edr-agent.exe"
$cfg = "C:\ProgramData\EDRAgent\config\config.toml"   # sc.exe qc で確認
$url = "http://【サーバーIP】:8080/api/v1/agents/download?platform=windows&arch=amd64"
$sum = "http://【サーバーIP】:8080/api/v1/agents/download/checksum?platform=windows&arch=amd64"

sc.exe stop EDRAgent
$tmp = "$env:TEMP\edr-agent.new"
Invoke-WebRequest -Uri $url -OutFile $tmp -UseBasicParsing
# SHA-256 検証
$exp = ((Invoke-WebRequest $sum -UseBasicParsing).Content | ConvertFrom-Json).checksum.ToLower()
$act = (Get-FileHash $tmp -Algorithm SHA256).Hash.ToLower()
if ($act -ne $exp) { throw "checksum mismatch" }
Copy-Item $tmp $bin -Force
# ★整合性サイドカーを更新（存在する場合）— 下記の注意を参照
$sidecar = Join-Path (Split-Path $cfg -Parent) "agent.sha256"
if (Test-Path $sidecar) { [IO.File]::WriteAllText($sidecar, $act) }
sc.exe start EDRAgent
```

```bash
# Linux 例（ExecStart のバイナリ・config を systemctl cat <service> で確認）
SVC=edr-agent; BIN=/opt/edr-agent/edr-agent; CFG=/etc/edr-agent/config.toml
URL="http://【サーバーIP】:8080/api/v1/agents/download?platform=linux&arch=amd64"
sudo systemctl stop "$SVC"
sudo curl -fsSL "$URL" -o /tmp/edr-agent.new
# （SHA-256 検証は /api/v1/agents/download/checksum で取得した値と sha256sum を比較）
sudo install -o root -m 755 /tmp/edr-agent.new "$BIN"
# ★整合性サイドカー更新（存在する場合）
SIDE="$(dirname "$CFG")/agent.sha256"
[ -f "$SIDE" ] && printf '%s' "$(sha256sum "$BIN" | awk '{print $1}')" | sudo tee "$SIDE" >/dev/null
sudo systemctl start "$SVC"
```

> **★ バイナリ自己整合性チェックに注意:** エージェントは起動時に自身のバイナリ SHA-256 を `<config-dir>/agent.sha256` の保存値と照合します（`integrity.Check`）。**バイナリだけ差し替えて保存ハッシュを更新しないと「エージェントバイナリの改ざんを検知しました」エラーを出し続け、サーバーへ偽の改ざんアラートを上げる恐れ**があります（起動自体は継続）。手動更新では上記のとおりサイドカーを新バイナリのハッシュ（bare hex・改行なし）で更新してください。サイドカーが存在しない端末（整合性機能以前のビルド）はエージェントが初回起動時に自動生成するため更新不要です。

## 5. 手動インストール（上級者向け）

スクリプトを使用せず手動でインストールする手順です。

### 5-1. バイナリのビルド

```bash
cd agent
go build -o edr-agent ./cmd/agent
```

### 5-2. クライアント証明書の生成

```bash
# エージェント側で実行
openssl genrsa -out agent.key 2048
openssl req -new -key agent.key -out agent.csr \
  -subj "/CN=$(hostname)/O=EDR Agent/C=JP"

# サーバー管理者にCSRを渡し、署名された agent.crt と ca.crt を受け取る
```

### 5-3. 設定ファイルの作成

`/etc/edr-agent/config.toml`（または任意のパス）を作成します。詳細は[設定ファイルのリファレンス](#6-設定ファイルのリファレンス)を参照してください。

### 5-4. 動作確認

```bash
# フォアグラウンドで起動して動作確認
sudo ./edr-agent --config /etc/edr-agent/config.toml
```

## 6. 設定ファイルのリファレンス

設定ファイルは **TOML形式** です。インストールスクリプトで自動生成されますが、必要に応じて編集してください。

変更後はサービスの再起動なしに自動で再読み込みされます（60秒間隔）。

```toml
[agent]
# エージェントを一意に識別するID（自動生成）
id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
# ホスト名（自動検出）
hostname = "your-hostname"

[server]
# EDRサーバーのURL
url = "http://edr.example.com"
# gRPCポート（エンロールメント・コマンド受信用）
grpc_port = 9090
# Ingestion gRPCポート（テレメトリ送信用）
ingestion_grpc_port = 9091
# 接続タイムアウト（秒）
connect_timeout_sec = 30

[collection]
# --- 監視機能の有効/無効 ---
process_monitoring = true   # プロセス監視
file_monitoring = true      # ファイル監視
network_monitoring = true   # ネットワーク監視
dns_monitoring = true       # DNS監視
registry_monitoring = true  # レジストリ監視（Windowsのみ）
auth_monitoring = true      # 認証イベント監視
yara_scan_on_exec = true    # 実行時YARAスキャン

# イベント送信間隔（ミリ秒）
event_batch_interval_ms = 500

# オフライン時のローカルバッファサイズ
local_buffer_size_mb = 100

# 最大イベント処理数（毎秒）
max_events_per_second = 1000

# --- 監視対象の設定 ---
# 監視するパス（空=全て）
monitored_paths = []

# 監視から除外するパス
excluded_paths = [
  "/proc",
  "/sys",
  "/dev",
  "C:\\Windows\\WinSxS",
]

# 監視から除外するプロセス名
excluded_processes = [
  "edr-agent",
  "antivirus.exe",
]

[response]
# 自動対応機能（サーバーからのコマンド実行）
auto_response_enabled = true

[logging]
# ログレベル: debug, info, warn, error
level = "info"
# ログファイルのパス
file = "/var/log/edr-agent/agent.log"
# ログローテーション
max_size_mb = 100
max_backups = 5

[quarantine]
# 隔離ファイルの保存先
dir = "/var/lib/edr-agent/quarantine"
```

## 8. アンインストール

インストールスクリプトに対応したアンインストールスクリプトを使用してください。

### Linux / macOS

```bash
# 通常のアンインストール（ログ・データを保持）
```

```powershell
# サービスを停止・削除

Remove-Item -Recurse -Force "C:\ProgramData\EDRAgent"
```

## 9. トラブルシューティング

### 接続エラー（gRPC）

**症状**: ログに `connection refused` または `dial failed` が出る

**確認事項**:
1. サーバーのポート9091が開いているか確認（Windowsの場合）
   ```powershell
   Test-NetConnection -ComputerName 【サーバーIP】 -Port 9091
   ```
2. EC2のセキュリティグループでポート9091がエージェントマシンのIPから許可されているか確認
3. `config.toml` の `ingestion_grpc_port = 9091` が設定されているか確認

### eBPFエラー（Linux）

**症状**: `failed to load eBPF program` というエラー

**確認事項**:
1. Linuxカーネルバージョンが5.8以上か確認
   ```bash
   uname -r
   ```
2. 必要なカーネル機能が有効か確認
   ```bash
   grep -E "CONFIG_BPF|CONFIG_BPF_SYSCALL" /boot/config-$(uname -r)
   ```

**⚠️ より厄介なのは「エラーが出ない」ケース**: eBPF がロードできない／`-tags ebpf` なしでビルドされた
エージェントは、**エラーを出さずに** inotify（ファイル）と `/proc/net` ポーリング（ネットワーク）へ
フォールバックして動き続ける。この状態では

- ファイルイベントに操作元 pid が載らない → **ランサムウェア検知(T1486)が無反応**
- ESTABLISHED しか観測できない → **ポートスキャン(T1046)が不可視**

となるが、ログにもアラートにも異常は現れない。判別方法と正しいビルド・配備手順は
[eBPFエージェント ビルドと配備ランブック.md](eBPFエージェント%20ビルドと配備ランブック.md) を参照。

### サービスが起動しない（Windows）

```powershell
# Windowsイベントログでエラーを確認
Get-EventLog -LogName System -Source "Service Control Manager" -Newest 10

# バイナリのバージョン確認
& "C:\Program Files\EDR Agent\edr-agent.exe" --version

# フォアグラウンドで起動してエラーを確認
& "C:\Program Files\EDR Agent\edr-agent.exe" --config "C:\Program Files\EDR Agent\config.toml"
```

### サーバー側にエージェントが表示されない

1. ingestionサーバーにハートビートが届いているかログを確認
   ```bash
   docker compose logs ingestion | grep "【エージェントID】"
   ```
2. `config.toml` の `[agent]` セクションでIDとホスト名が設定されているか確認
3. `[server]` セクションの `url`・`ingestion_grpc_port` が正しいか確認
