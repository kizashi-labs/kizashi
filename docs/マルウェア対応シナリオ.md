# マルウェア検知後の対応シナリオ

> Kizashi プラットフォームを使用した、マルウェア検知から収束までの実践的な対応手順書です。

---

## 対応フローチャート（共通）

```mermaid
flowchart TD
    A([🔔 アラート発生]) --> B[/アラート画面で確認\n/alerts]
    B --> C{重大度判定}
    C -->|Critical / High| D[インシデント作成\n/incidents]
    C -->|Medium 以下| E[調査継続]
    D --> F[エンドポイント隔離\n/endpoints → 隔離]
    E --> F
    F --> G[ライブレスポンスで調査\n/live-response]
    G --> H[証拠収集\n/forensics]
    H --> I{悪意あり確認}
    I -->|Yes| J[脅威除去\n検疫ファイル /quarantine]
    I -->|No| K[誤検知として抑制\n/suppressions]
    J --> L[隔離解除・復旧]
    K --> L
    L --> M[インシデントクローズ\nレポート作成]
    M --> N([✅ 対応完了])

    style A fill:#e8002d,color:#fff
    style N fill:#22c55e,color:#fff
    style D fill:#ff6b35,color:#fff
    style F fill:#1a6bff,color:#fff

```

### フェーズ別目安時間

| フェーズ | 目安時間 |
|---|---|
| トリアージ（重大度判定） | 〜5 分 |
| 初動分析（プロセス・通信確認） | 〜10 分 |
| 封じ込め（隔離実施） | 〜15 分 |
| 詳細調査（フォレンジクス） | 30 分〜数時間 |
| 復旧（除去・正常化確認） | 数時間〜1 日 |
| 事後対処（抑制ルール・レポート） | 〜1 時間 |

## シナリオ 1 — ランサムウェア検知

### 状況
エンドポイント `WIN-SALES-042` にて、`vssadmin.exe` によるシャドーコピー削除と大量ファイル暗号化の動きが検知された。

### 対応手順

**1. アラート確認（/alerts）**
- アラート一覧を開き、`WIN-SALES-042` のアラートを確認する
- 重大度 **Critical**、検知ルール「Ransomware Shadow Copy Deletion」であることを確認
- **インシデントとして起票** ボタンをクリックし `/incidents` に記録する

**2. エンドポイント隔離（/endpoints）**
- エンドポイント一覧で `WIN-SALES-042` を検索
- 「隔離」ボタンをクリック → ネットワーク通信を即座に遮断
- 隔離ステータスが `Isolated` に変わったことを確認

**3. ライブレスポンスで調査（/live-response）**
- `WIN-SALES-042` を選択してリモートシェルを起動
- 実行中のプロセスを確認：
  ```
  Get-Process | Where-Object {$_.CPU -gt 50}
  ```
- 不審なプロセス（例：`svchost_upd.exe`）の PID を特定し強制終了

**4. フォレンジクス収集（/forensics）**
- メモリダンプを取得して暗号化プロセスの実行痕跡を保全
- 自動実行エントリを確認（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`）

**5. 脅威除去・復旧**
- 検疫ファイル（/quarantine）で隔離された暗号化実行ファイルを確認・完全削除
- バックアップから影響ファイルをリストア
- 隔離解除前に追加スキャンを実施

**6. 事後対処**
- `/rules` で同一パターンを検知するカスタムルールを追加
- `/incidents` でインシデントをクローズし、レポート（/reports）を生成

## シナリオ 2 — マルウェアドロッパー検知

### 状況
`DEV-WORKSTATION-07` にて、PowerShell が外部 URL からペイロードをダウンロードし実行した痕跡が検知された。

### 対応手順

**1. アラート確認（/alerts）**
- 「PowerShell Encoded Command Execution」アラートを確認
- エンコードされたコマンド（Base64）をデコードし内容を確認
- 通信先 IP・ドメインを IOC として `/ioc` に登録

**2. 脅威インテリジェンスと照合（/threat-intel）**
- 通信先 IP を脅威インテリジェンスフィードで照合
- 既知 C2 サーバーであれば即時隔離に移行

**3. エンドポイント隔離（/endpoints）**
- `DEV-WORKSTATION-07` を隔離し、横断感染（ラテラルムーブメント）を防止

**4. ライブレスポンスで詳細調査（/live-response）**
- ドロップされたファイルのパスを特定：
  ```
  Get-ChildItem -Path $env:TEMP -Recurse | Where-Object {$_.LastWriteTime -gt (Get-Date).AddHours(-2)}
  ```
- ファイルのハッシュ値を取得して `/ioc` に追加登録

**5. MITRE ATT&CK マッピング（/mitre）**
- 使用された TTP（例：T1059.001 PowerShell, T1105 Ingress Tool Transfer）を記録
- 同一キャンペーンの他端末への感染有無をスレットハンティング（/threat-hunting）で確認

**6. 事後対処**
- PowerShell 実行ポリシーを制限する EDR ポリシーを `/playbooks` で自動化
- 同一 IOC をブロックする抑制ルールを `/suppressions` に追加

## シナリオ 3 — インフォスティーラー検知

### 状況
`FIN-LAPTOP-019` にて、ブラウザ認証情報データベース（`Login Data`）への不審なアクセスと外部への HTTPS 通信が検知された。

### 対応手順

**1. アラート確認（/alerts）**
- 「Credential Access: Browser Credential Dumping」アラートを確認
- 外部通信先（IP・ドメイン）を記録

**2. ネットワーク分析（/network）**
- 当該エンドポイントの過去 24 時間の通信ログを確認
- 外部へのデータ送信量・通信パターンを確認し、情報窃取の範囲を把握

**3. エンドポイント隔離（/endpoints）**
- `FIN-LAPTOP-019` を即座に隔離し、追加の認証情報流出を防止

**4. ライブレスポンスで調査（/live-response）**
- スティーラーの実行ファイルを特定：
  ```
  Get-Process | Select-Object Name, Path, Id | Format-List
  ```
- ブラウザプロファイルのアクセス時刻を確認して影響範囲を特定

**5. 影響範囲の評価と対応**
- 窃取された可能性のある認証情報（業務システム・クラウドサービス等）のパスワードを即時リセット
- MFA（多要素認証）が未設定のサービスを確認し、有効化を依頼

**6. 事後対処**
- 検疫ファイル（/quarantine）でスティーラー本体を削除
- `/vulnerabilities` で侵入経路となった脆弱性を確認しパッチ適用
- 脆弱性スキャンを再実施して修正を確認
- インシデントレポートにデータ漏洩の可能性を明記し、必要に応じてコンプライアンス報告（/compliance）を実施
