## 1. 画面構成の基本

### ナビゲーション構造

画面左側のアイコンレール（サイドバー）から各グループを選択すると、サブメニューが展開されます。

| 操作 | 内容 |
|------|------|
| アイコンをクリック | サブメニューを展開／閉じる |
| サブメニュー項目をクリック | 対象ページへ移動 |
| サイドバースクロール | 多数のアイコンがある場合は縦スクロール可能 |

### トップバー右上

| 要素 | 操作 |
|------|------|
| `Ctrl+K` / `⌘K` | グローバル検索を起動 |
| ベルアイコン | 通知センターを開く（未読件数バッジ） |
| ユーザーアバター（頭文字） | クリックでメニュー表示。ユーザー名・ロール確認、ログアウト |

### 管理メニューの表示条件

サイドバー下部の **管理** グループは **adminロール** のユーザーにのみ表示されます。
管理グループはさらに「コア」「検知」「ハンティング & 調査」など複数のサブグループに分かれています。

| ルール一覧 | 左ペイン **検知** → **検知ルール** |
| ルール有効化／無効化 | 一覧のトグルスイッチをクリック |

### 2-4. アラート抑制（`/suppressions`）

誤検知を抑制するルールを設定します。

| 操作 | 手順 |
|------|------|
| 抑制ルール作成 | **検知** → **アラート抑制** → **＋追加** |
| 条件設定 | ルール名 / 送信元IP / プロセス名 / ファイルハッシュ などの条件を組み合わせて設定 |
| 有効期限設定 | 抑制ルールに有効期限（日時）を設定して自動解除 |

> ⚠️ **条件を空にして保存しないこと。** `conditions={}` のルールは **すべてのアラートに一致するキャッチオール** として動作し、全検知が無効化されます。ルールを作成する際は必ず 1 件以上の条件を設定してください。空条件ルールが is_active=true で存在しないか、定期的に以下のクエリで確認することを推奨します。
>
> ```sql
> SELECT id, name, is_active, conditions
> FROM suppression_rules
> WHERE conditions::text = '{}'
>   AND is_active = true;
> ```
>
> 該当ルールが見つかった場合は即座に無効化してください（`UPDATE suppression_rules SET is_active=false WHERE id='<id>';`）。詳細は `docs/runbook.md` の「抑制ルール キャッチオール検出・無効化」を参照。

| グループ割り当て | 詳細画面 → **グループ** ドロップダウンで変更 |

### 3-2. ライブレスポンス（`/live-response`）

稼働中のエンドポイントにリモートでコマンドを実行する機能です。

#### 画面構成

左パネルに4つのタブがあります（縦リスト形式）：

| タブ | 内容 |
|------|------|
| **エージェント** | オンラインのエンドポイント一覧。クリックでセッション開始 |
| **セッション** | アクティブ・アイドル中のセッション一覧。再開・終了が可能 |
| **テンプレート** | よく使うコマンドのプリセット（プロセス/ネットワーク/ファイル/システム/永続性） |
| **履歴** | 過去に実行したコマンドと出力の一覧 |

#### 操作手順

| 操作 | 手順 |
|------|------|
| セッション開始 | **エージェント** タブ → 対象エンドポイントをクリック |
| コマンド実行 | ターミナル画面でコマンドを入力して `Enter` |
| Tab補完 | コマンド途中で `Tab` キーを押すと候補が表示される |
| コマンド履歴 | `↑` / `↓` キーで過去のコマンドを呼び出せる |
| 強制中断 | `Ctrl+C` で実行中のコマンドを中断 |
| 画面クリア | `Ctrl+L` またはゴミ箱アイコン |
| セッション終了 | ターミナルヘッダーの ■ ボタン |
| セッション再開 | **セッション** タブ → **セッションを再開** ボタン |

> ⚠️ ライブレスポンスの操作はすべて監査ログに記録されます。

#### 8-2-1. mTLS 証明書自動更新

エージェントが保持する mTLS 証明書の有効期限は、サーバが自動的に監視・更新します。

**動作概要**:
- APIサービスの `AgentCertRenewer` スケジューラが **24時間ごと** に有効期限 30 日以内の証明書を検出
- 検出されたエージェントへ NATS 経由で更新命令を送信
- エージェントが新しい鍵ペアと CSR を生成し、サーバに署名を依頼
- 署名済み証明書をアトミックに書き込み後、gRPC 接続を自動再接続

**管理コンソールで確認できる情報**:

| 項目 | 場所 |
|---|---|
| 証明書有効期限 | エージェント詳細 → 証明書情報 |
| 最終接続日時 | エージェント一覧 → `last_seen` 列 |

**手動確認 (DB直接)**:
```sql
SELECT hostname, cert_not_after,
       cert_not_after - NOW() AS remaining
FROM agents
WHERE cert_not_after IS NOT NULL
ORDER BY cert_not_after;
```

> 証明書更新に失敗した場合は `docs/runbook.md` の「Agent mTLS 証明書自動更新 (更新失敗時)」を参照してください。

### 8-5. 自動リメディエーション管理（`/admin/remediation`）

#### ルール管理

| 操作 | 手順 |
|------|------|
| ルール一覧 | **管理** → **対応** → **自動修復ルール** |
| ルール追加 | `POST /api/v1/admin/remediation/rules` に JSON でトリガー条件とアクションを定義 |

#### 除外リスト（重要インフラ保護）

自動リメディエーションを**実行させてはならないホスト**（ドメインコントローラー、本番 DB サーバー等）を除外リストに登録します。登録されたホストへの自動隔離・プロセス終了・ファイル検疫は発動しません。

| 操作 | 手順 |
|------|------|
| 除外一覧取得 | `GET /api/v1/admin/remediation/exclusions` |

### 8-18. MDM（モバイルデバイス管理）（`/admin/mobile-device-management`）

iOS / Android 端末を Apple Business Manager / Android Enterprise 連携で管理するためのコンソール。上部に 5 つのタブ（デバイス / プロファイル / アプリ / コマンド履歴 / 統合設定）が並びます。

#### 8-18-1. デバイス一覧タブ

| 操作 | 手順 |
|------|------|
| フィルター | 上部チップで Platform（iOS / Android / Windows Mobile / Other）、右側ドロップダウンで Compliance を絞り込み |
| Re-evaluate ボタン | 各行右端の「Re-evaluate」をクリックすると、signal 列（暗号化 / 画面ロック / Jailbreak）から `compliance_status` を自動再計算します |
| 手動 override | API 経由で `PATCH /api/v1/admin/mobile-devices/:id/compliance` に `{"compliance_status":"<value>"}` を送ると operator が明示値を書き込めます（値は `compliant` / `non_compliant` / `unknown` / `pending` のいずれか） |

**Re-evaluate のルール**: `jailbroken == true` または `encryption_enabled == false` または `screen_lock_enabled == false` のいずれかで `non_compliant`、3 列すべて健全なら `compliant`。

#### 8-18-2. コマンド履歴タブ

キューに投入したリモート操作（デバイスロック / ワイプ / 紛失モード など）の実行状態を追跡します。

| 状態 | 意味 | 取れるアクション |
|------|------|----------------|
| `queued` | MDM サーバーから端末へ未送信 | **キャンセル** ボタン |
| `sent` | 端末へ送信済み、応答待ち | **更新** ボタン / 30 秒ごとに自動更新 |
| `acknowledged` | 端末が成功応答 | なし（履歴として保持） |
| `failed` | 端末が失敗応答 または AMAPI エラー | なし |
| `expired` | 期限切れで端末に届かなかった | なし |

**自動更新バッジ**: `sent` 行が 1 件以上ある間、ヘッダーに「自動更新 N 件」バッジが表示され、30 秒ごとに backend が AMAPI へ状態を取りに行きます。iOS コマンドは端末側から `/ios/server` に応答するため server-side poll は no-op（情報メッセージのみ）。

**更新ボタン**: operator が明示的に「今すぐ取りに行きたい」時に使用。Android は AMAPI へ即座に poll、iOS は「端末次第です」という note を表示。

#### 8-18-3. 統合設定タブ

ABM / Android Enterprise / SCEP / APNs の 4 カードで資格情報を管理。

| 操作 | 手順 |
|------|------|
| 資格情報のアップロード | カード内「アップロード」ボタン → ファイル選択（ABM: p7m または JSON、AE: SA キー JSON、APNs: .p12） |
| Sync 実行 | カード内「Sync」ボタン → upstream API 疎通確認 + デバイス一覧取り込み（ABM / AE のみ） |
| 資格情報の期限確認 | Sync 実行後、各カード下部にカラー付きバッジで残り日数が表示される |

**期限バッジの色**: スケジューラの severity と同じ閾値で色分けされるため、アラート発火タイミングと画面上の警告レベルが一致します。
- **赤** : 期限切れ / 本日期限切れ / 残り 1 日未満
- **オレンジ** : 残り 7 日未満
- **黄色** : 残り 30 日未満
- **グレー** : 残り 30 日以上

**期限アラート**: `mdm_integrations.credential_expiry` は毎回 Sync のタイミングで永続化され、バックグラウンドスケジューラが日次で判定します。残り **30 日 / 7 日 / 1 日** のしきい値でそれぞれ `severity 3 / 7 / 9` のアラートが `/alerts` に作成されます。同一統合の重複アラートは 24 時間 dedupe。

### 8-19. AI 利用ログ（`/admin/ai-usage`）

AI アシスト機能（アラート解析・AI チャット・AI 検知ルール生成等）の呼び出し履歴を管理します。AI opt-in テナントを対象に Anthropic へのデータ送信を監査するためのログで、APPI 第27条・第28条に基づく第三者提供記録として機能します（v1.3.9〜v1.3.14 で全 7 関数をカバー）。

#### 画面の確認方法

| 確認項目 | 手順 |
|---------|------|
| ログ一覧 | **管理** → **レポート & コンプライアンス** → **AI 利用ログ** |
| フィルター | 機能名 (`function_name`) / 日時範囲 / 成否でフィルタリング可能 |
| 詳細確認 | 各行をクリックしてプロンプト文字数・レスポンス文字数・レイテンシ・マスクトークン数を確認 |

#### ログに記録される情報

| フィールド | 内容 |
|----------|------|
| `function_name` | 呼び出した AI 機能（AnalyzeAlert / ExplainEvent / RecommendResponse / ChatQuery / AnalyzeThreat / Chat / GenerateDetectionRule） |
| `model` | 使用した Anthropic モデル名（例：claude-sonnet-4-6） |
| `related_id` | 関連するアラート ID またはインシデント ID |
| `triggered_by` | 操作を実行したユーザー（メールアドレス） |
| `tokens_masked` | sanitizer が置換したトークン数（データ最小化の証跡） |
| `prompt_chars` / `response_chars` | 送信・受信したテキスト文字数 |
| `latency_ms` | Anthropic API の応答時間（ミリ秒） |
| `success` | 呼び出しの成否 |
| `error_class` / `error_message` | 失敗時のエラー情報 |
| `called_at` | 呼び出し日時（UTC） |

#### 保持ポリシー

AI 利用ログは **呼び出し日から 1 年間** 保持され、その後 `RetentionCleaner` によって自動削除されます（v1.3.15 で実装、毎日 0 時台に実行）。

```sql
-- ログ件数の確認
SELECT function_name, count(*), min(called_at), max(called_at)
FROM ai_usage_logs
GROUP BY function_name
ORDER BY count DESC;

-- 直近 24 時間のエラー確認
SELECT function_name, error_class, error_message, called_at
FROM ai_usage_logs
WHERE success = false
  AND called_at > NOW() - INTERVAL '24 hours'
ORDER BY called_at DESC;
```

> 保持クリーナーが停止している疑いがある場合は `docs/runbook.md` の「AI 利用ログ保持クリーナー障害」を参照してください。

> **プラン要件:** AI 利用ログを含む AI 関連 4 画面（AIアシスタント／AI自動トリアージ／AI自動調査／AI利用ログ）は `ai_investigation` 機能（**Professional プラン以上**）が必要です。下位プランではサイドバーに 🔒 が表示されます。

| エージェント接続 | オンライン／オフラインのエンドポイント数 |

### 9-5. LDAP / AD連携（`/admin/integrations/ldap`）

| 操作 | 手順 |
|------|------|
| LDAP設定 | **管理** → **統合** → **LDAP/AD連携** |
| サーバー設定 | ホスト / ポート / ベースDN / バインドDN / パスワードを入力 |
| ユーザー同期 | **今すぐ同期** ボタン |
| グループマッピング | LDAPグループ → Kizashi ロールのマッピングを設定 |
| TLS | `ldaps://` または StartTLS を有効化（本番環境では必須） |
