### T1069 / T1087 — 経路の全損だった

07-26 の主因は検知能力の欠落ではなく **server-detect 経路の全損**だった。当時のアラート実体
（`alerts-WIN-ENDPOINT-01-20260726.json`）は窓内6件がすべて `[Sigma]`=builtin で、
`[SIGMA]`(DBルール) も `[BEHAVIORAL]`/`[HEURISTIC]`/`[DISCOVERY]`(状態付き検知器) も
1件も無い。今回は両経路が生きており、被覆していた DB ルール
`Network Discovery via net.exe`(migration 019) がそのまま発火した。

**この解消は PR #643 で追加した builtin の効果ではない。** サーバのコンテナイメージは
main マージでは自動デプロイされず（`docker.yml` の手動 dispatch が必要）、#643/#653/#654 は
いずれも本番未反映のままである。追加した builtin は冗長化として有効だが**実機未検証**。

### T1110 — 修正と欠陥が別経路にあった

**採点上は初回から「Tactic」だったが、実質的な未検知だった。** 紐付いたのは
`[SIGMA] SAM Hive Dump (DB)`（直前の T1003.002）で、同じ credential-access 戦術を共有する
`shareTactic` で加点されただけ。ブルートフォース自体は何も検知していない。
**採点の数字だけを見ると解消したように見える**ので、この種の加点は個別に確認が要る。

実測すると `auth` イベントが **0 件**だった。原因は P5-26 のとおり:

- 07-26 に直した `timediff()` は**ポーリング**経路のクエリ
- この環境は `EDR_AGENT_ETW=1` のため**購読**経路（`EvtSubscribe`）を通っていた
- 症状（auth 0 件）が同じだったため、07-26 レポートは「解消済み」と記録していた

購読経路の欠陥は `EvtNext` が FALSE を返したときに戻り値だけを見て「もう無い」と解釈して
いたこと。シグナルは自動リセットで消費済みのため保留バッチが取り残される。修正後:

```
10:41:18  auth×7 (failed / success=false / edr-final-1..7)
10:41:20  [BEHAVIORAL] SSH ブルートフォース検知
10:41:21  [BEHAVIORAL] パスワードスプレー攻撃（多数アカウントへの認証失敗）
10:41:21  [HEURISTIC] パスワードスプレーの疑い（T1110.003）   ← MTTD 2秒
```

なおランナーの `failed-logon-burst` は**7個の異なるアカウントに1回ずつ**失敗させるため、
`bruteMinFails=6`（単一アカウント基準）には原理的に到達しない。成立するのは
**パスワードスプレー経路**（`sprayMinAccounts=6`）である。

### #2 は「直したら誤検知が生まれた」型

購読を直して auth イベントが届くようになった直後、**存在しないアカウントに対して
severity 8 の「ブルートフォース成功＝アカウント侵害」**が出た。1回の失敗試行につき
4625 と 4648 がペアで届き、4648 を無条件に `Success=true` としていたため。
本物のブルートフォース攻撃中に正規プロセスが 4648 を出すだけで再現する。

### #4 は手順書が実行不能だった

`deploy/validation/README.md` は `powershell -ExecutionPolicy Bypass -File .\atomic-runner-compact.ps1`
と書いているが、スクリプトは UTF-8 BOM 無しで日本語コメントを含むため、Windows PowerShell 5.1 が
ANSI として読んで構文エラーになる。07-26 レポートに「ランナー: `atomic-runner-compact.ps1` **相当**」
とあるのは、ファイル実行ではなくコンソール貼り付けで回避していたためと思われる。
今回は BOM 付きの複製を `%TEMP%` に作って回避した。
