# 検知率向上 2026-07-20(4) — field-support 到達性の是正と同期ガード

## 背景

⑩ ランサム検知が本番で無反応だった不具合（`action` vs `operation`、PR #491）を機に、
「エージェント/ingestion が実際に emit しているのに検知側がそのフィールドを認識していない」
系統の**到達性の穴**を体系的に洗い出した。

`SupportedSigmaFields()`（`field_support.go`）は、curate の**field-support ゲート**と builtin
**inert 監査**の両方が「どのテレメトリ・フィールドが利用可能か」を判断する基準表。ここに
欠落があると、**実在するフィールドを参照する Sigma/SigmaHQ ルールが誤って inert 判定／
curate で defer** され、検知が静かに抑制される。

## 発見

ingestion（`handler.go`）が emit する flat キーと `SupportedSigmaFields()` を突き合わせた結果、
**emit されているのに supported に無い実イベントフィールド**が判明：

| フィールド | イベント | 消費者 |
|---|---|---|
| `bytes_sent` / `bytes_recv` | network | ⑫ 持ち出しボリューム検知 |
| `state` | network（接続状態） | netScan（refused 判定） |
| `old_path` | file（リネーム元） | — |
| `file_size` | file | — |

`bytes_sent` と `state` は**現に検知器が消費している**のに supported 表に無く、これらを参照する
ルールは誤って defer される状態だった。

## 修正

1. `SupportedSigmaFields()` に上記5フィールドを追加。これで network 量／接続状態／ファイル
   リネーム・サイズを参照する Sigma/SigmaHQ ルールが field-supported となり、curate ゲートで
   有効化可能になる（＝検知対象ルールが増える）。
2. **同期ガード**テスト `TestEmittedEventFieldsAreSupported` を追加。ingestion が各イベント種別で
   emit する flat フィールド一覧（`emittedEventFields`、handler.go をミラー）を保持し、その全てが
   `SupportedSigmaFields()` に含まれることを保証。**今回のような「emit されているのに未サポート」を
   自動検出**し、サイレントな検知抑制（⑩系）の再発を防ぐ。
3. inert 監査の `knownInert` 許可リストから、既に field-supported になっていた2件
   （"Security Audit Log Cleared" / "Multiple Failed Login Attempts"）を除去（監査が resolved と報告。
   ブルートフォースは⑨のリアルタイム検知が本命に）。監査対象の inert は 4→2 に減少（残りは
   Sysmon EID10 / file Contents の真のセンサーギャップ）。

## 効果

- **field-support ゲートの精度向上** → network 量・接続状態・ファイルリネーム/サイズ系の
  SigmaHQ ルールが誤 defer されず有効化できる（検知率の底上げ）。
- **サイレント抑制の再発防止**：emit フィールドと supported フィールドの乖離を CI で自動検出。
- 監査許可リストを実態に同期。
