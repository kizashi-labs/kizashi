# EDR Platform — Demo Environment

A fully self-contained demo environment for customer presentations, proof-of-concept evaluations, and internal testing. All services run in Docker on a single laptop. No internet connection is required after images are pulled.

---

## Prerequisites

| Requirement | Minimum | Recommended |
|---|---|---|
| Docker Desktop | 4.26+ | Latest |
| RAM available to Docker | 6 GB | 8 GB |
| Free disk space | 8 GB | 15 GB |
| CPU cores (Docker limit) | 2 | 4 |
| OS | macOS 13+, Windows 10+, Ubuntu 20.04+ | — |

> **Windows users:** Ensure WSL 2 backend is enabled in Docker Desktop settings.

---

## Quick Start

```bash
# Clone or enter the project directory
cd edr-platform

# Start all demo services in the background
docker compose -f deploy/docker-compose.demo.yml up -d

# Watch startup progress (Ctrl-C to stop following)
docker compose -f deploy/docker-compose.demo.yml logs -f
```

All services are healthy and ready when `docker compose ps` shows every container as `healthy`. This typically takes 60–90 seconds on first run (images need to be pulled) and around 20 seconds on subsequent runs.

## Resetting the Demo

To wipe all data and restore the pristine demo state:

```bash
# From the project root directory
./deploy/demo/reset-demo.sh
```

The reset script:
1. Stops all demo containers
2. Deletes all demo Docker volumes (database, Grafana state, metrics, NATS data)
3. Restarts the containers
4. Waits for PostgreSQL to initialise and apply seed data
5. Prints a credentials summary

### Reset options

```bash
# Skip the confirmation prompt (useful for CI / automated demos)
./deploy/demo/reset-demo.sh --yes

# Stop and reset without restarting services
./deploy/demo/reset-demo.sh --yes --no-start

# Show help
./deploy/demo/reset-demo.sh --help
```

## Stopping the Demo

```bash
# Stop containers (preserves data volumes)
docker compose -f deploy/docker-compose.demo.yml stop

# Stop and remove containers (preserves data volumes)
docker compose -f deploy/docker-compose.demo.yml down

# Full teardown — removes containers AND all demo data volumes
docker compose -f deploy/docker-compose.demo.yml down -v
```

## Troubleshooting

### Containers fail to start

```bash
# Check logs for all services
docker compose -f deploy/docker-compose.demo.yml logs

# Check a specific service
docker compose -f deploy/docker-compose.demo.yml logs api
docker compose -f deploy/docker-compose.demo.yml logs postgres
```

### Port already in use

If ports 3000, 8080, or 3001 are occupied by another process:

```bash
# macOS / Linux
lsof -i :3000
lsof -i :8080
lsof -i :3001

# Windows (PowerShell)
netstat -ano | findstr ":3000"
```

Stop the conflicting process, then restart the demo.

### PostgreSQL not ready / seed data missing

The seed SQL file is applied by PostgreSQL's `docker-entrypoint-initdb.d` mechanism, which only runs when the data volume is empty (first start). If you see missing data:

```bash
# Check postgres initialisation logs
docker compose -f deploy/docker-compose.demo.yml logs postgres | grep -E "(seed|init|error|ERROR)"

# Force a full reset which empties the volume
./deploy/demo/reset-demo.sh --yes
```

### Frontend shows "Cannot connect to API"

The frontend connects to the API at `http://localhost:8080`. Verify the API is healthy:

```bash
curl http://localhost:8080/health
```

If the API is not responding, check its logs and ensure the database and NATS are healthy first (the API has `depends_on` conditions for both).

### Grafana dashboards are empty / no data

Prometheus scrapes the API and detection engine metrics. If those services just started, allow 60 seconds for the first scrape cycle. For missing historical data, note that Prometheus only retains 7 days in demo mode and starts with an empty TSDB.

### Docker Desktop running out of memory

Increase the memory limit in Docker Desktop settings (Resources > Memory) to at least 6 GB. After changing the limit, restart Docker Desktop.

### Images not found (offline environment)

Pull images on a machine with internet access, save them, and load on the target:

```bash
# Pull and save (internet-connected machine)
docker compose -f deploy/docker-compose.demo.yml pull
docker save timescale/timescaledb:latest-pg16 nats:2-alpine \
  prom/prometheus:v2.51.0 grafana/grafana:10.4.2 \
  | gzip > edr-demo-images.tar.gz

# Load on the air-gapped machine
docker load < edr-demo-images.tar.gz

# Application images must be built from source
docker compose -f deploy/docker-compose.demo.yml build
```
