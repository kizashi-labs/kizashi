# サーバに無い宛先（書き込み）の内訳

フロントエンドが `apiFetch` で呼んでいる書き込み（POST/PUT/PATCH/DELETE）のうち、
`server/internal/api` にルートが1本も無いものの一覧です。**150件**あります。

> **訂正**: この文書は一度「131件」と書いていました。数え漏らしです。
> 20画面が書き込みを `lib/persist` の `persist()` に移していて、これは
> `apiFetch` を包む関数なのですが、当時の走査は `apiFetch` しか見ていません
> でした。**エンドポイントを1つも直していないのに19件が計測から消え、
> 減ったように見えていました。** 走査は両方の綴りを見るようになっています。

生成方法は `frontend/tests/lib/server-routes.test.ts` と同じで、gin のルート登録を
Go ソースから、呼び出し先を TypeScript ソースから読んで突き合わせています。同ファイルが
件数の上限を固定しているので、この表より増えるとテストが落ちます。

## 何が起きるか

呼び出しは 404 になります。多くの画面はそれを `.catch` で握りつぶし、
ローカルの状態だけを進めて成功のトーストを出していました（その33件は
`silent-writes.test.ts` で対処済みで、いまは「保存できませんでした」と出ます）。
つまり**押した操作は一度も保存されていません**。

## すでに直したもの（動詞・経路の取り違え、9件）

サーバ側に実装があるのに、フロント側が別の動詞や経路で呼んでいたものです。
これらは判断を要さないので直してあります。

| 呼んでいた宛先 | 実際のルート | 画面 |
|---|---|---|
| `PATCH /admin/drp/findings/:id` | `PUT` | ブランド保護 |
| `PATCH /dark-web/findings/:id` | `PUT` | ダークウェブ監視 |
| `PATCH /admin/feed-analytics/:id/status` | `PUT` | フィード分析 |
| `PUT /process-rules/:id/toggle` | `PATCH` | プロセス許可リスト |
| `PATCH /escalation-rules/:id` | `PATCH …/:id/toggle` | エスカレーション |
| `PUT /suppressions/:id`（切替） | `PUT …/:id/toggle` | 抑制ルール |
| `PUT /admin/integrations/elastic/mappings` | `POST` | Elastic連携 |
| `PUT /admin/integrations/sentinel/mappings` | `POST` | Sentinel連携 |
| `PATCH /privacy/incidents/:id` | `PUT`（下記注） | プライバシー侵害記録 |

**プライバシー侵害記録だけは動詞の付け替えでは済みませんでした。**
サーバの `UpdateIncident` は全項目を置き換える実装なので、
`{reported_to_authority: true}` だけを PUT すると `incident_type`・
`description`・`severity`・`status`・`remediation_steps` が空文字で、
`affected_subjects_count` が 0 で上書きされます。GDPR の侵害記録そのものが
消えるので、既存の値を全部添えて送るようにしました。
