## 台帳の構成

項目本体は優先度ごとに `docs/debt/` に分かれています。この索引は「どの ID が
どこにあるか」だけを持ちます。

分割の理由は実測されたコストです。2026-08-03 の 1 日で、単一ファイルの末尾に
全 PR が追記する構造が原因の事故が 5 件起きました:

- 番号衝突 3 件（P5-11 が `agents.os` と LOLBin で、P5-15 が Wazuh と
  Defender で二重に採番された）。別の場所への追記どうしは git が競合として
  検出しないため、**同じ番号の節が 2 つ並んだ状態でクリーンにマージされます**。
- マージ解決時の節の消失 2 件（P5-11 / P5-12 が main から消えた。内容自体は
  P5-17 / P5-18 として再採番のうえ再着地しており、失われてはいません）。

分割は「競合が起きる範囲を狭める」だけで、上の 2 つはどちらも競合を伴わずに
起きる**サイレントな**事故です。そちらは `server/internal/store/debt_ledger_test.go`
の CI ゲートで捕捉します（ID の重複禁止、索引と本体の相互一致、退役 ID の明示）。

## 優先度の考え方

商用EDR製品として、優先度は次の順で判断します。

1. **信頼性・安全性の毀損**（偽データ・認証バイパス）= 製品の存在意義を否定するため最優先
2. **セキュリティ品質**（SAST 未処理・lint 不足）
3. **テスト・保守性**
4. **機能カバレッジ**（準備中ページの実装）
