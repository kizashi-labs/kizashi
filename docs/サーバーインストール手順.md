## 1. システム要件

### ハードウェア要件

| 規模 | CPU | RAM | ストレージ |
|------|-----|-----|----------|
| 小規模（〜50エンドポイント） | 2コア | 4GB | 100GB SSD |
| 中規模（〜500エンドポイント） | 4コア | 8GB | 500GB SSD |
| 大規模（500以上） | 8コア以上 | 16GB以上 | 1TB以上 SSD |

### ソフトウェア要件

- **OS**: Linux (Ubuntu 22.04 LTS / Debian 12 推奨), Windows 10/11, Windows Server 2022
- **Docker**: 24.0 以上
- **Docker Compose**: 2.20 以上

### ネットワーク要件

| ポート | プロトコル | 用途 |
|--------|-----------|------|
| 3000 | TCP | 管理Web UI（フロントエンド） |
| 8080 | TCP | REST API |
| 9090 | TCP | gRPC（APIサービス / エージェント登録） |
| 9091 | TCP | gRPC（Ingestionサービス / エージェントイベント受信） |

## 2. 事前準備

### 2-1. Docker / Docker Compose のインストール

**Ubuntu / Debian**:
```bash
# Dockerのインストール
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker

# バージョン確認
docker --version
docker compose version
```

**Windows**:
[Docker Desktop for Windows](https://docs.docker.com/desktop/install/windows-install/) をインストールしてください。

### 2-2. リポジトリの取得

```bash
git clone https://github.com/your-org/edr-platform.git
cd edr-platform
```

## 3. インストール手順

### 3-1. 環境変数の設定（任意）

デフォルト設定でそのまま起動できますが、本番環境では `.env` ファイルを作成して設定を変更してください。

```bash
cp .env.example .env
```

主な設定項目：

```env
# データベース（デフォルト: edr_dev_password）
POSTGRES_PASSWORD=【強力なパスワードを設定】

# JWT署名秘密鍵（デフォルト: dev-jwt-secret-change-in-production-32chars）
JWT_SECRET=【ランダムな長い文字列】

# フロントエンドポート（デフォルト: 3000）
FRONTEND_PORT=3000

# APIポート（デフォルト: 8080）
API_PORT=8080

# AI自動調査（任意）: 高重大度アラートをAIで自動分析
OPENAI_API_KEY=sk-...        # OpenAI gpt-4o を使用する場合
ANTHROPIC_API_KEY=sk-ant-... # Claude をフォールバックに使用する場合

# VirusTotal API（任意）
VIRUSTOTAL_API_KEY=【VirusTotalのAPIキー】
```

> `OPENAI_API_KEY` または `ANTHROPIC_API_KEY` が設定されると、重大度7以上のアラート発火時にAIによる自動調査が実行されます。未設定の場合はスキップされ、手動トリガーのみ利用できます。

> **セキュリティ注意**: 本番環境では必ず `POSTGRES_PASSWORD` と `JWT_SECRET` を変更してください。`.env` ファイルはGitにコミットしないでください。

### 3-2. サービスの起動

```bash
docker compose up -d
```

起動するサービス：

| サービス | コンテナ名 | 役割 |
|---------|-----------|------|
| `postgres` | `kizashi-postgres` | TimescaleDB（データ永続化） |
| `nats-1` | `kizashi-nats-1` | NATS JetStream ノード1（クラスタシード） |
| `nats-2` | `kizashi-nats-2` | NATS JetStream ノード2 |
| `nats-3` | `kizashi-nats-3` | NATS JetStream ノード3 |
| `api` | `kizashi-api` | REST APIサーバー + マイグレーション自動実行 |
| `ingestion` | `kizashi-ingestion` | gRPCサーバー（エージェントからのイベント受信） |
| `detection` | `kizashi-detection` | 検知エンジンサーバー |
| `frontend` | `edr-frontend` | Next.js 管理Web UI |

> NATS は3ノードクラスタで動作します。1ノード障害時も継続稼働します。

初回起動時はDockerイメージのビルドが行われるため、数分かかります。

## 4. 初期設定

### 4-1. データベースマイグレーション

`api` サービス起動時に `RUN_MIGRATIONS=true` が設定されているため、**マイグレーションは自動的に実行**されます。手動で実行する場合：

```bash
# 全マイグレーションファイルを番号順に実行
for f in server/migrations/*.sql; do
  echo "Applying $f..."
  docker exec -i kizashi-postgres psql -U edr -d edrplatform < "$f"
done
```

### 4-2. 管理者アカウント

インストール直後のログイン情報：

| 項目 | 値 |
|------|-----|
| メールアドレス | `admin@example.com` |
| パスワード | `Admin1234!` |

> **重要**: 初回ログイン後、必ずパスワードを変更してください。

ブラウザで `http://localhost:3000` にアクセスしてログインしてください。

### 4-3. エンロールメントトークンの生成

エージェントをインストールする前に、エンロールメントトークンを生成します。

1. Web UIにログイン
2. **管理** → **管理 & 設定** → **エージェント登録承認**
3. 生成されたトークンをメモ（エージェントインストール時に使用）

## 5-2. Kubernetes / Helm によるデプロイ（本番推奨）

Docker Compose の代わりに Kubernetes + Helm でデプロイする場合：

### 前提条件

- Kubernetes クラスタ（1.26 以上）
- Helm 3.12 以上
- `kubectl` が設定済み

### インストール

```bash
# リポジトリルートから実行
helm install kizashi deploy/helm/kizashi \
  --namespace kizashi --create-namespace \
  --set global.postgresql.password=【DBパスワード】 \
  --set global.jwtSecret=【JWT秘密鍵】 \
  --set ingress.host=edr.example.com \
  --set ingress.tls.enabled=true
```

### 主な values パラメータ

| パラメータ | デフォルト | 説明 |
|-----------|----------|------|
| `global.postgresql.password` | — | PostgreSQL パスワード（必須） |
| `global.jwtSecret` | — | JWT 署名鍵（必須） |
| `ingress.host` | `edr.local` | 外部公開ホスト名 |
| `ingress.tls.enabled` | `false` | TLS 有効化（cert-manager 連携） |
| `api.replicaCount` | `2` | API サーバーのレプリカ数 |
| `api.autoscaling.enabled` | `false` | HPA（水平自動スケール）有効化 |
| `monitoring.serviceMonitor.enabled` | `false` | Prometheus ServiceMonitor |

詳細は [deploy/helm/kizashi/README.md](../deploy/helm/kizashi/README.md) を参照してください。

## 6. アップデート手順

> ⚠️ **重要 (1)**: 開発環境でコミットした変更をサーバーに反映するには、**事前に `git push` が必要**です。`git push` せずにサーバーで `git pull` しても変更は届きません。

> ⚠️ **重要 (2)**: サーバー側の `docker compose up` には **必ず `--build` を付けてください**。`--build` を省くと `git pull` でソースを更新しても既存の Docker イメージが再利用され、コード変更が一切反映されません。

> ⚠️ **重要 (3)**: コマンドは **`~/edr-platform`（リポジトリルート）で実行**してください。`deploy/` サブディレクトリで実行すると別の compose スタック (`deploy-*` コンテナ) が更新され、実際にリクエストを受けている `kizashi-*` スタックは変わりません。

```bash
# ── 開発環境（ローカル）で実行 ──
git add <変更ファイル>
git commit -m "fix: ..."
git push origin main          # ← 必須！これをしないとサーバーに届かない

# ── サーバー（EC2等）で実行 ──
cd ~/edr-platform             # ← リポジトリルートで実行すること
git pull origin main

# APIのみ更新（推奨: 他サービスを停止しない）
docker compose up -d --build --no-deps api

# フロントエンドのみ更新
docker compose up -d --build --no-deps frontend

# 全サービス更新
docker compose up -d --build

# データベースマイグレーション（新しいマイグレーションファイルがある場合）
docker exec -i kizashi-postgres psql -U edr -d edrplatform \
  < server/migrations/【新しいマイグレーションファイル】.sql
```

**デプロイ確認**

```bash
# コンテナの状態確認（kizashi-api が "healthy" になっているか）
docker ps --format "table {{.Names}}\t{{.Status}}" | grep kizashi

# ログに起動メッセージが出ているか確認
docker logs kizashi-api 2>&1 | tail -20
```

> ブラウザのキャッシュが残っている場合は **Ctrl+Shift+R**（強制リロード）で最新版を表示してください。

## 7. トラブルシューティング

### サービスが起動しない

```bash
# ログで原因を確認
docker compose logs 【サービス名】

# コンテナの状態確認
docker compose ps
```

### データベース接続エラー

```bash
# PostgreSQL接続確認
docker exec -it kizashi-postgres psql -U edr -d edrplatform -c "SELECT 1;"

# マイグレーション状態確認
docker exec -it kizashi-postgres psql -U edr -d edrplatform -c "\dt"
```

### ログイン認証エラー

```bash
# admin ユーザーのハッシュを再生成（Go bcrypt形式）
docker run --rm golang:1.22-alpine sh -c \
  'cat > /tmp/hash.go << '"'"'EOF'"'"'
package main
import (
  "fmt"
  "golang.org/x/crypto/bcrypt"
)
func main() {
  h, _ := bcrypt.GenerateFromPassword([]byte("Admin1234!"), 12)
  fmt.Println(string(h))
}
EOF
cd /tmp && go mod init hash && go get golang.org/x/crypto/bcrypt && go run hash.go'

# DB上のパスワードハッシュを更新
docker exec -it kizashi-postgres psql -U edr -d edrplatform \
  -c "UPDATE users SET password_hash='【上記ハッシュ】' WHERE email='admin@example.com';"
```

### gRPCポートへの接続確認

```bash
# ポート疎通確認
nc -zv localhost 9091
```

### フロントエンドが表示されない

```bash
# フロントエンドのビルドログ確認
docker compose logs frontend

# フロントエンドの再ビルド
docker compose build frontend
docker compose up -d frontend
```

### ingestion サービスのクラッシュ

`docker-compose.yml` の `ingestion` サービスに以下の環境変数が設定されているか確認してください：

```yaml
TLS_ENABLED: "false"
TLS_CERT_FILE: ""
TLS_KEY_FILE: ""
```

## 8. アンインストール手順

> **注意**: アンインストールを実行するとデータベースのデータが完全に削除されます。必要に応じて事前にバックアップを取得してください。

### 8-1. バックアップ（推奨）

アンインストール前にデータをバックアップします。

```bash
# データベースのバックアップ
docker exec kizashi-postgres pg_dump -U edr edrplatform \
  | gzip > edrplatform_backup_$(date +%Y%m%d_%H%M%S).sql.gz

echo "バックアップ完了"
```

### 8-2. サービスの停止

```bash
# 全サービスを停止（コンテナのみ削除、データは保持）
docker compose down
```

### 8-3. コンテナ・イメージ・ボリュームの削除

#### データを含む完全削除（推奨）

```bash
# コンテナ・ネットワーク・ボリュームをすべて削除
docker compose down --volumes --remove-orphans

# ビルド済みイメージも削除する場合
docker compose down --volumes --remove-orphans --rmi all
```

#### データを残してコンテナのみ削除

```bash
# コンテナとネットワークのみ削除（ボリュームのデータは保持）
docker compose down --remove-orphans
```

削除されるリソース：

| リソース | 削除コマンド | 内容 |
|---------|------------|------|
| コンテナ | `down` | 全サービスのコンテナ |
| ネットワーク | `down` | `kizashi-internal`, `kizashi-external` |
| ボリューム | `--volumes` | DB データ、NATSデータ、Grafanaデータ |
| イメージ | `--rmi all` | `edr-platform-api` 等のビルド済みイメージ |

### 8-4. ファイルの削除

```bash
# プロジェクトディレクトリの削除
cd ..
rm -rf edr-platform
```

### 8-5. Kubernetes / Helm の場合

```bash
# Helm リリースの削除
helm uninstall kizashi --namespace kizashi

# Namespace ごと削除（PVC も含む）
kubectl delete namespace kizashi
```

PersistentVolumeClaim（PVC）が残る場合は手動で削除してください：

```bash
kubectl get pvc -n kizashi
kubectl delete pvc --all -n kizashi
```

### 8-6. アンインストール確認

```bash
# コンテナが残っていないことを確認
docker compose ps

# ボリュームが削除されたことを確認
docker volume ls | grep kizashi

# ネットワークが削除されたことを確認
docker network ls | grep kizashi
```

いずれも出力が空であればアンインストール完了です。
