# Kizashi — Agent Code Signing Guide

## 1. Overview

EDR agents operate at a privileged level on every endpoint in your organization's fleet.
Code signing establishes a cryptographic chain of trust between Kizashi's release
pipeline and the binary that executes on each host. Without valid signatures:

- **Windows** SmartScreen and enterprise AppLocker/WDAC policies will block or warn on
  the agent installer and service binary.
- **macOS** Gatekeeper will quarantine unsigned binaries; system extensions require both
  a Developer ID signature and Apple notarization to load.
- **Linux** package managers, AIDE, and custom integrity policies may reject binaries
  that lack a verifiable GPG signature.

Beyond OS-level enforcement, signed binaries give customers an auditable proof that the
file they are running was produced by Kizashi's build pipeline and has not been
tampered with in transit or at rest.

## 2. Prerequisites

### Certificates and Keys

| Platform | Artifact | Issuer |
|----------|----------|--------|
| Windows  | EV Code Signing Certificate (PFX/PEM) | DigiCert, Sectigo, GlobalSign |
| macOS    | Developer ID Application certificate  | Apple Developer Program ($99/yr) |
| Linux    | GPG keypair (4096-bit RSA or Ed25519)  | Self-managed; publish to keyserver |

### Tools

| Tool | Version | Install |
|------|---------|---------|
| `signtool.exe` | Windows SDK 10+ | Visual Studio / Windows SDK |
| `codesign` | macOS built-in | Xcode Command Line Tools |
| `notarytool` | macOS 13+ built-in | Xcode 13+ |
| `stapler` | macOS built-in | Xcode Command Line Tools |
| `gpg` | GnuPG 2.2+ | `apt install gnupg2` / `brew install gnupg` |
| `osslsigncode` | 2.x | For cross-signing Windows binaries on Linux CI |

### Environment Variables (CI/CD)

```
SIGN_CERT_PATH        # Path to PFX file (Windows)
SIGN_CERT_PASSWORD    # PFX password (store as secret)
APPLE_TEAM_ID         # 10-character Apple Team ID
APPLE_ID              # Apple ID email for notarization
APPLE_APP_PASSWORD    # App-specific password for notarytool
APPLE_KEYCHAIN_PROFILE # Keychain profile name (CI use)
GPG_KEY_ID            # GPG key fingerprint or email
GPG_PASSPHRASE        # GPG key passphrase (store as secret)
```

## 3. Windows Code Signing

### Certificate Requirements

Use an **Extended Validation (EV)** code signing certificate. EV certificates provide
immediate SmartScreen reputation; standard OV certificates require accumulated download
history before SmartScreen stops warning users. EV certificates are stored on a hardware
token (FIPS 140-2 Level 2) — for CI/CD, use a cloud HSM service such as DigiCert
KeyLocker or SSL.com eSigner.

### Signing with signtool.exe

```bat
REM Sign the agent service binary
signtool.exe sign ^
  /fd sha256 ^
  /tr http://timestamp.digicert.com ^
  /td sha256 ^
  /f "%SIGN_CERT_PATH%" ^
  /p "%SIGN_CERT_PASSWORD%" ^
  /d "Kizashi Agent" ^
  /du "https://kizashi-edr.example.com" ^
  dist\edr-agent-windows-amd64.exe

REM Verify the signature immediately after signing
signtool.exe verify /pa /v dist\edr-agent-windows-amd64.exe
```

Key flags:
- `/fd sha256` — use SHA-256 as the file digest algorithm (SHA-1 is deprecated).
- `/tr` + `/td sha256` — RFC 3161 timestamp server with SHA-256 digest; ensures the
  signature remains valid after certificate expiry.
- `/pa` in verify — use the default authentication policy.

### Dual-Signing (SHA-1 + SHA-256)

For compatibility with Windows 7/2008 R2 endpoints still in some enterprise fleets,
append a second signature block:

```bat
signtool.exe sign /as /fd sha256 /tr http://timestamp.digicert.com /td sha256 ^
  /f "%SIGN_CERT_PATH%" /p "%SIGN_CERT_PASSWORD%" ^
  dist\edr-agent-windows-amd64.exe
```

### SmartScreen Reputation

After signing, submit the binary to Microsoft's reputation system by uploading to
https://www.microsoft.com/en-us/wdsi/filesubmission. Enterprise customers can also use
WDAC (Windows Defender Application Control) policies referencing the certificate's
Common Name to whitelist the agent unconditionally.

## 4. macOS Code Signing and Notarization

### Certificate Setup

1. In Xcode, open **Accounts** and add your Apple ID.
2. Under your team, click **Manage Certificates** and create a
   **Developer ID Application** certificate.
3. Export as `.p12` for CI use; import into the CI keychain.

### Signing with codesign

```bash
# Sign the universal binary (amd64 + arm64 lipo'd together, or sign individually)
codesign --sign "Developer ID Application: Kizashi Inc (${APPLE_TEAM_ID})" \
  --timestamp \
  --options runtime \
  --entitlements deploy/macos/entitlements.plist \
  --force \
  dist/edr-agent-darwin-universal

# Verify locally before notarization
codesign --verify --deep --strict --verbose=2 dist/edr-agent-darwin-universal
```

Key flags:
- `--timestamp` — embed a secure timestamp from Apple's timestamp server.
- `--options runtime` — enables Hardened Runtime, required for notarization.
- `--entitlements` — declare only the entitlements the agent actually needs
  (e.g., `com.apple.security.cs.allow-unsigned-executable-memory` if needed by eBPF).

### Notarization with notarytool

```bash
# Store credentials in keychain once (locally or in CI ephemeral keychain)
xcrun notarytool store-credentials "${APPLE_KEYCHAIN_PROFILE}" \
  --apple-id "${APPLE_ID}" \
  --team-id "${APPLE_TEAM_ID}" \
  --password "${APPLE_APP_PASSWORD}"

# Submit for notarization and wait for result
xcrun notarytool submit dist/edr-agent-darwin-universal \
  --keychain-profile "${APPLE_KEYCHAIN_PROFILE}" \
  --wait \
  --output-format json | tee notarization-result.json

# Check result
STATUS=$(jq -r '.status' notarization-result.json)
if [ "$STATUS" != "Accepted" ]; then
  echo "Notarization failed: $STATUS"
  xcrun notarytool log "$(jq -r '.id' notarization-result.json)" \
    --keychain-profile "${APPLE_KEYCHAIN_PROFILE}"
  exit 1
fi
```

### Stapling

Staple the notarization ticket to the binary so Gatekeeper can verify it offline:

```bash
xcrun stapler staple dist/edr-agent-darwin-universal
xcrun stapler validate dist/edr-agent-darwin-universal
```

For `.pkg` installers, staple to the package instead of the inner binary:

```bash
xcrun stapler staple dist/KizashiEDR.pkg
```

## 5. Linux GPG Signing

### Generating a Dedicated Signing Key

Create a dedicated offline key for release signing — do not use a personal GPG key.

```bash
# Generate a 4096-bit RSA key (or use --quick-gen-key for Ed25519)
gpg --full-generate-key
# Select: (1) RSA and RSA, keysize 4096, expiry 2y
# UID: Kizashi Release Signing <releases@kizashi-edr.example.com>

# Export the public key for distribution
gpg --armor --export "${GPG_KEY_ID}" > kizashi-edr-release-signing.asc

# Export secret key for secure offline backup
gpg --armor --export-secret-keys "${GPG_KEY_ID}" > OFFLINE_BACKUP_release-signing-private.asc
```

Publish the public key to a keyserver and to your documentation:

```bash
gpg --keyserver hkps://keys.openpgp.org --send-keys "${GPG_KEY_ID}"
```

### Signing Binaries

Create a detached ASCII-armored signature alongside each binary:

```bash
for BINARY in dist/edr-agent-linux-amd64 dist/edr-agent-linux-arm64; do
  gpg --batch --yes \
    --pinentry-mode loopback \
    --passphrase-fd 0 \
    --local-user "${GPG_KEY_ID}" \
    --armor \
    --detach-sign \
    "${BINARY}" <<< "${GPG_PASSPHRASE}"
  # Produces: ${BINARY}.asc
done
```

### SHA-256 Checksum File

Supplement GPG signatures with a signed checksums file (similar to Debian/Ubuntu):

```bash
cd dist
sha256sum edr-agent-linux-amd64 edr-agent-linux-arm64 > SHA256SUMS
gpg --batch --yes --pinentry-mode loopback --passphrase-fd 0 \
  --local-user "${GPG_KEY_ID}" --armor --detach-sign SHA256SUMS \
  <<< "${GPG_PASSPHRASE}"
# Produces: SHA256SUMS.asc
```

### Verification by End Users

```bash
# Import Kizashi public key
gpg --import kizashi-edr-release-signing.asc
# or from keyserver:
gpg --keyserver hkps://keys.openpgp.org --recv-keys <FINGERPRINT>

# Verify binary signature
gpg --verify edr-agent-linux-amd64.asc edr-agent-linux-amd64

# Verify checksums
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum --check SHA256SUMS
```

## 6. Automated Signing in CI/CD

### GitHub Actions — Secrets Setup

Store all sensitive values as GitHub Actions **Encrypted Secrets** (Settings > Secrets
and variables > Actions). Never print secret values in logs.

| Secret Name | Content |
|-------------|---------|
| `WIN_SIGN_CERT_B64` | Base64-encoded PFX file |
| `WIN_SIGN_CERT_PASSWORD` | PFX password |
| `APPLE_DEVELOPER_P12_B64` | Base64-encoded .p12 certificate |
| `APPLE_DEVELOPER_P12_PASSWORD` | .p12 password |
| `APPLE_ID` | Apple ID email |
| `APPLE_APP_PASSWORD` | App-specific password |
| `APPLE_TEAM_ID` | 10-character team ID |
| `GPG_PRIVATE_KEY_B64` | Base64-encoded GPG private key |
| `GPG_PASSPHRASE` | GPG key passphrase |

### GitHub Actions Workflow Excerpt

```yaml
jobs:
  sign-and-release:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        include:
          - os: windows-latest
            target: sign-windows
          - os: macos-latest
            target: sign-macos
          - os: ubuntu-latest
            target: sign-linux

    steps:
      - uses: actions/checkout@v4

      - name: Download unsigned agent binaries
        uses: actions/download-artifact@v4
        with:
          name: agent-binaries-unsigned
          path: downloads/

      # Windows: decode and sign
      - name: Decode Windows signing certificate
        if: runner.os == 'Windows'
        shell: pwsh
        run: |
          [IO.File]::WriteAllBytes("cert.pfx",
            [Convert]::FromBase64String("$env:WIN_SIGN_CERT_B64"))
        env:
          WIN_SIGN_CERT_B64: ${{ secrets.WIN_SIGN_CERT_B64 }}

      - name: Sign Windows agent
        if: runner.os == 'Windows'
        run: make sign-windows
        env:
          SIGN_CERT_PATH: cert.pfx
          SIGN_CERT_PASSWORD: ${{ secrets.WIN_SIGN_CERT_PASSWORD }}

      # macOS: import keychain, sign, notarize
      - name: Import Apple Developer certificate
        if: runner.os == 'macOS'
        run: |
          echo "$APPLE_DEVELOPER_P12_B64" | base64 --decode > dev_id.p12
          security create-keychain -p ci-keychain-password ci.keychain
          security default-keychain -s ci.keychain
          security unlock-keychain -p ci-keychain-password ci.keychain
          security import dev_id.p12 -k ci.keychain \
            -P "$APPLE_DEVELOPER_P12_PASSWORD" -T /usr/bin/codesign
          security set-key-partition-list -S apple-tool:,apple: \
            -s -k ci-keychain-password ci.keychain
        env:
          APPLE_DEVELOPER_P12_B64: ${{ secrets.APPLE_DEVELOPER_P12_B64 }}
          APPLE_DEVELOPER_P12_PASSWORD: ${{ secrets.APPLE_DEVELOPER_P12_PASSWORD }}

      - name: Sign and notarize macOS agent
        if: runner.os == 'macOS'
        run: make sign-macos
        env:
          APPLE_TEAM_ID: ${{ secrets.APPLE_TEAM_ID }}
          APPLE_ID: ${{ secrets.APPLE_ID }}
          APPLE_APP_PASSWORD: ${{ secrets.APPLE_APP_PASSWORD }}
          APPLE_KEYCHAIN_PROFILE: kizashi-notarize

      # Linux: import GPG key, sign
      - name: Import GPG signing key
        if: runner.os == 'Linux'
        run: |
          echo "$GPG_PRIVATE_KEY_B64" | base64 --decode | \
            gpg --batch --import --pinentry-mode loopback \
                --passphrase-fd 3 3<<< "$GPG_PASSPHRASE"
        env:
          GPG_PRIVATE_KEY_B64: ${{ secrets.GPG_PRIVATE_KEY_B64 }}
          GPG_PASSPHRASE: ${{ secrets.GPG_PASSPHRASE }}

      - name: Sign Linux agent
        if: runner.os == 'Linux'
        run: make sign-linux
        env:
          GPG_KEY_ID: ${{ secrets.GPG_KEY_ID }}
          GPG_PASSPHRASE: ${{ secrets.GPG_PASSPHRASE }}

      - name: Upload signed binaries
        uses: actions/upload-artifact@v4
        with:
          name: agent-binaries-signed-${{ runner.os }}
          path: downloads/
```

## 7. Certificate Management

### Renewal Schedule

| Certificate | Typical Validity | Action |
|-------------|-----------------|--------|
| EV Code Signing (Windows) | 1–3 years | Renew 60 days before expiry; re-sign all release artifacts |
| Developer ID Application (macOS) | ~5 years | Renew through Apple Developer portal |
| GPG Release Signing Key | Set to 2 years | Extend or replace; publish new key with cross-signature |

Set calendar reminders 90 and 30 days before each expiry. DigiCert and Sectigo send
email reminders, but do not rely solely on vendor notifications.

### Revocation Procedures

**Windows EV Certificate Compromised:**
1. Contact the CA immediately to revoke the certificate.
2. Notify customers via your security advisory channel.
3. Re-sign all current release artifacts with the replacement certificate.
4. Update the CI/CD secret `WIN_SIGN_CERT_B64` with the new certificate.

**Apple Developer ID Compromised:**
1. Revoke the certificate in Apple Developer portal.
2. Re-sign and re-notarize all macOS artifacts.
3. Note: previously notarized and stapled binaries may stop validating once Apple
   processes the revocation through their OCSP responders.

**GPG Key Compromised:**
1. Generate a revocation certificate (should be pre-generated at key creation):
   ```bash
   gpg --gen-revoke "${GPG_KEY_ID}" > revoke.asc
   gpg --import revoke.asc
   gpg --keyserver hkps://keys.openpgp.org --send-keys "${GPG_KEY_ID}"
   ```
2. Generate a new keypair following Section 5.
3. Publish the new public key and update documentation.

### Key Storage Best Practices

- Store EV hardware tokens in a physical safe when not in use.
- For cloud HSM (DigiCert KeyLocker, AWS CloudHSM), enable multi-factor approval for
  signing operations.
- Never commit private keys, PFX files, or `.p12` files to version control.
- Rotate CI/CD secrets whenever team membership changes.

## 8. Verification Guide for End Users

This section is suitable for inclusion in customer-facing documentation.

### Windows

```powershell
# Right-click > Properties > Digital Signatures tab in Explorer, or:
Get-AuthenticodeSignature -FilePath .\edr-agent-windows-amd64.exe |
  Select-Object -Property Status, SignerCertificate

# Expected output:
# Status               SignerCertificate
# ------               -----------------
# Valid                [Subject: CN=Kizashi Inc, ...]
```

### macOS

```bash
# Verify code signature
codesign --verify --deep --strict --verbose=2 ./edr-agent-darwin-universal

# Verify notarization ticket is stapled
xcrun stapler validate ./edr-agent-darwin-universal

# Check Gatekeeper assessment
spctl --assess --type exec --verbose ./edr-agent-darwin-universal
# Expected: ./edr-agent-darwin-universal: accepted
```

### Linux

```bash
# Import Kizashi public key (one-time)
curl -fsSL https://releases.kizashi-edr.example.com/signing-key.asc | gpg --import

# Verify binary
gpg --verify edr-agent-linux-amd64.asc edr-agent-linux-amd64
# Expected: Good signature from "Kizashi Release Signing <releases@...>"

# Verify checksums
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum --check SHA256SUMS
# Expected: edr-agent-linux-amd64: OK
```

If verification fails, do **not** run the binary. Contact Kizashi support at
security@kizashi-edr.example.com and provide the output of the verification command.
