# 検知率向上サマリ 2026-07-15 — Windows横展開の深化・クラウド永続化・ランサム複合相関

「検知率を高める他の方法」からの継続作業。既存の基礎検知（PsExec/WinRM/クラウドIAM/ランサム個別前兆）を土台に、
**より深いテレメトリ軸**と**複数シグナルの相関**で検知精度・被覆を底上げした3テーマの記録。

---

## 1. Windows横展開の深化 — 「ツールの存在」から「実ペイロード」へ

### 課題
既存の `PsExec Remote Execution` / `WinRM Lateral Movement` ルールは、`psexec.exe`/`PSEXESVC.exe`/`winrs`/
`Enter-PSSession` といった**ツールの存在**しか見ておらず、リモートで**実際に何が実行されたか**を捉えていな
かった。svchostハロウイング検知（`Svchost With Non-Standard Parent`）で確立した「疑わしい親プロセスの
子プロセスを見る」パターンを、横展開の実行痕跡に横展開した。

### 追加ルール（`sigma_builtins.go`）
| ルール | 技術 | 検知条件 |
|---|---|---|
| Process Spawned by PsExec Service (Attacker Payload) | T1569.002 | `ParentImage` が `PSEXESVC.exe` = リモートで実行された実コマンド |
| Process Spawned by WinRM Remote Shell Host (Attacker Payload) | T1021.006 | `ParentImage` が `wsmprovhost.exe` = PSRemoting経由の実コマンド |
| PsExec-Alternative Remote Execution Tool (PAExec/RemCom) | T1569.002 | `paexec.exe`/`paexecsvc.exe`/`remcom.exe`/`remcomsvc.exe` = 署名回避クローンツール |
| PowerShell Remote Command Execution via Invoke-Command | T1021.006 | `Invoke-Command` + `-ComputerName`/`-Session` = 対話セッション無しの一括実行 |
| WinRM Remote Management Enabled | T1021.006 (low) | `winrm quickconfig`/`Enable-PSRemoting`/`AllowUnencrypted` = 横展開の前段有効化 |

否定テスト: 通常のサービスホスト経由cmd／explorer経由のインタラクティブpowershell／ローカルscriptblock／
読取専用`winrm get`はいずれも非発火（`builtin_lateral_deep_fire_test.go`）。

## 2. クラウド永続化 — バックドアアカウントとイベント駆動再起動

既存のIAM特権昇格・サーバレス改ざん検知に、**攻撃者が資格情報ローテーションを生き延びるための2手口**を追加。

| ルール | 技術 | 検知条件 |
|---|---|---|
| Cloud Backdoor Account Creation (IAM User / Service Principal) | T1136.003 | AWS `iam create-user` / GCP `iam service-accounts create`+`keys create` / Azure `ad sp create-for-rbac` 等 |
| Cloud Persistence via Scheduled Event Trigger (EventBridge/Cloud Scheduler) | T1053.005（クラウド版） | `events put-targets` が Lambda/SSM/Step FunctionsのARNを指す、またはGCP `scheduler jobs create` |

読取専用のIAM一覧・SNS宛てターゲット（compute起動ではない）は非発火（`builtin_cloud_persist_fire_test.go`）。

## 3. ランサムウェア複合相関 — 前兆シグナルの併発を検知

### 洞察
復旧妨害（シャドウコピー/バックアップ削除、T1490）・防御サービス改ざん（T1489）・広範囲ACL付与（T1222）は、
既存ルールが個別にも高/重大レベルで発火する。しかし**正規の管理作業がこれら複数を短時間に併発することは
通常なく**、2系統以上の併発は暗号化直前の高信頼シグナルになる。

### 実装
`ransomware_correlator.go`（`RansomwareCorrelator`）を新規実装し、`engine.go` に配線:

- **設計**: C2相関器（`C2Correlator`）と同じ windowed・bounded-key・多信号昇格パターン。ただし
  **agentIDのみでキーイング**（ホスト単位。C2相関器はPID/宛先単位）— ランサム前兆はホスト全体に及ぶ挙動のため。
- **窓**: 15分（C2の30分より短い — 実際の暗号化前シーケンスは数分単位で展開するため）。
- **分類子**: `classifyRansomwareSignal` が MITRE タグのプレフィックス（T1490/T1489/T1222）でマッチの軸を分類。
- **昇格**: 2軸一致で sev10 + 自動隔離。3軸目でも成長のみ再発火（同一集合の再観測では再発火しない）。
- **配線位置**: `engine.go` の `matches` に対し、`ProcessThreatCorrelator`（侵害↔C2相関）と同じ位置
  （キルチェーン相関の直前）で `classifyRansomwareSignal` により軸分類し `Observe` へ供給。

### テスト（`ransomware_correlator_test.go`）
2軸発火(sev10+隔離) / 3軸目での再発火(成長) / 同一集合の再発火抑制 / 別ホスト非相関 / 窓外失効 /
未知シグナル無視 / `classifyRansomwareSignal`のMITREタグ分類。

### 価値
大規模暗号化が始まる**前**に介入できる、EDRにとって最も価値の高いタイミングでの検知。個別ルールが単発で
埋もれがちな「防御解除→復旧妨害」という定番シーケンスを、相関で確実に拾い上げる。
