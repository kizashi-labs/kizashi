# 本流へ渡す作業一覧

> **読む人**: 本流（生成器）側を触れる人。
> **これだけで足ります。** 受け側の事情を知らなくても、下の 3 件を
> 入れれば済むように書いてあります。

このリポジトリは本流のスナップショットで、生成のたびに木がまるごと
差し替わります。**生成側が何かを落とすと、その PR は緑のまま入ります。**

実際に **3 度**起きました（#67 で入れ、#70 で消え、#73 で戻し、#74 でまた
消えた）。#74 では受け側のガードが **64 件**を数えました —— そこには
**ガード自身の 3 ファイル**も含まれています。

受け側のガードは「**消されたことに気づく**」までしかできません。
**消されなくする**には、下の 3 件が生成器側に要ります。

経緯と受け側の作りは
[同期の受け側ガードと本流への反映.md](同期の受け側ガードと本流への反映.md)
にあります。**渡すだけならこの文書で足ります。**

---

## 1. やること（3 件）

> **どこに入れるか。** 3 件とも「木を生成したあとの調整」です。生成器の
> `scripts/public-snapshot/` に、すでに同じ段があります —— 配られた木の
> `scripts/mutations/NOT_SHIPPED.txt` は 1 行目にこう書いてあります:
>
> ```
> # この配置が同梱しないファイル。scripts/public-snapshot/adjust-mutations.py が
> # 生成する。手で編集しない（次の生成で上書きされる）。
> ```
>
> **この配置に届いている生成器の手がかりは、この 1 行だけです。**
> 下の 3 件も、木を配ったあとに同じところから呼んでください。

### 1-1. `timeout-minutes` 49 件と、欠落検査と、ローカルの写し

生成器側で 49 件を残すか、`workflow-lint.yml` を**再生成の対象から外す**か、
生成のあとに**下の道具を呼ぶ**か。どれも入れないと 4 度目が起きます
（3 度起きています —— #67 → #70 → #73 → #74）。

現物は §2 の表です。数字は実測（直近 200 runs）の成功時最大に余裕を
足したもので、**遅い日を殺さず、ハングは早く切る**幅にしてあります。

**表を書き写す必要はありません。** §2 の表は手で書いた散文ではなく、
`scripts/handover_timeouts.py --apply` の出力で、同じ道具が逆向きにも
走ります:

```sh
# 配った木に対して、生成のあとに 1 回
# （`scripts/public-snapshot/adjust-mutations.py` と同じ段）
python3 scripts/handover_timeouts.py --restore .
```

持っていくのは 2 つです —— **道具**（`scripts/handover_timeouts.py`）と
**値**（この文書）。木に無い上限だけを、`runs-on:` の次の行と、
名前で見つけた step の中に入れます。

- **冪等です。** すでに入っている値は触りません。
- **違う値が入っていたら上書きしません** —— どちらが正しいかは、
  道具には決められません。名指しで報告して 1 を返します。
- **改名された step は、黙って飛ばしません。** 本流は step を改名するので、
  見つからない行が出るのは想定内です。**想定内だから黙る**のがいちばん
  危ない —— 飛ばすと、その step の上限だけが消えます。

これで生成器側の作業は「49 か所に書き写す」ではなく「**1 つ呼ぶ**」に
なります。§1-3 の較正の道具と同じ形です。

欠落検査の本体:

- `.github/workflows/workflow-lint.yml`
  - `timeout-minutes` が無いジョブ → 落とす（既定が **6 時間**である
    説明つき）
  - `timeout-minutes > 60` → 落とす（「**ハングを上限の引き上げで
    直さないでください**」）
- `scripts/verify.sh` — 同じ判定の写しを、**領域に関係なく毎回**走らせる節

`workflow-lint.yml` を `ci.yml` の中に置いていないのは意図です。
**ci.yml が起動しないなら検査も動かない**ので、別ファイルにしてあります。

なぜ上限が要るのか（実測）:

| ジョブ | 中央 | 最悪 |
| --- | --- | --- |
| `agent-build (linux/amd64/ebpf)` | 1.7 分 | **360.3 分**（＝既定 6 時間の上限に当たって停止） |
| `rules-validate` | 1.2 分 | **111.2 分** |

どちらも `apt-get` の取得で止まっていました。**落ちないので誰も気づかず、
予算だけが減ります。**

### 1-2. `agent-ebpf.yml` の `mkdir -p downloads` の位置

再試行ループの**内側**に置いてください。`downloads/` は `.gitignore` に
入っているのでクローン直後には存在せず、**再試行の間に挟まる
`git reset --hard` が消します。**

この 1 行で、このワークフローはこのリポジトリで初めて成功しました
（それまで 4/4 失敗、すべて同じ位置）。

**この step は PR では走りません**（`if: github.ref == 'refs/heads/main'`）。
つまり**消えても PR は緑です。**

### 1-3. 生成器から較正の道具を呼ぶ

```sh
# ここも `scripts/public-snapshot/` の、木を配ったあとの段です
python3 scripts/recalibrate_ratchets.py --apply
python3 scripts/reanchor_mutations.py --apply
```

**順番が要ります。** 固定値を下げたあと、その値を参照している変異仕様書の
pattern も一緒に動かさないと、**下げた瞬間に仕様書が死にます。**

これを入れないと、ラチェット 16 本は「生成のたびに約 50 個の固定値を
測り直す負担」として、また配布から外されます（#70 がそうしました）。
道具は #75 で作ってあります —— **呼ばれていないだけです。**

受け側は**緩んだ結果**を落とすようにしましたが、それは事後です。
値が動かない回は素通りしますし、緩んだと分かっても受け側では直せません
（正しい値は生成器側でしか測れません）。**呼ぶこと自体は、ここでしか
入れられません。**

## 3. 数え直し方

```sh
python3 scripts/handover_timeouts.py            # 表と実物が合っているか
python3 scripts/handover_timeouts.py --print    # 実物から表を出す
python3 scripts/handover_timeouts.py --apply    # 表を実物に合わせて書き直す
```

`--check` は受け側の `workflow-lint.yml` と `scripts/verify.sh` の両方で
走ります。**合計だけでなく 1 行ずつ**見るので、値が 1 つ書き換わっても
落ちます —— 合計は動かないので、そこだけを見ていると素通りします。

道具ごと消えた木で数えるなら、下でも足ります:

```sh
cd .github/workflows
python3 - <<'PY'
import glob, yaml
job = step = 0
for f in sorted(glob.glob('*.yml')):
    for jn, j in (yaml.safe_load(open(f)).get('jobs') or {}).items():
        t = j.get('timeout-minutes')
        print(f"{f}\t{jn}\t{t if t is not None else 'MISSING'}")
        job += t is not None
        for s in (j.get('steps') or []):
            if 'timeout-minutes' in s:
                step += 1
                print(f"    ↳ {s.get('name') or s.get('uses')}\t{s['timeout-minutes']}")
print(f"job={job} step={step} total={job+step}")
PY
```

`MISSING` が 1 つでも出たら、`workflow-lint` と `sync-guard` の両方が
落ちます。

## 4. 受け側にある関連ファイル

写すときの参照用です。**何を守っているかは、コードのコメントが正です。**

| ファイル | 何が書いてあるか |
| --- | --- |
| `.github/workflows/workflow-lint.yml` | 欠落検査の本体（§1-1） |
| `scripts/handover_timeouts.py` | この表を生成し、木へ戻す道具（§1-1・§3） |
| `scripts/handover_timeouts_test.py` | その道具の判定を留めるもの |
| `scripts/verify.sh` | 同じ判定のローカルの写し（§1-1） |
| `.github/workflows/agent-ebpf.yml` | `mkdir -p downloads` の位置（§1-2） |
| `scripts/recalibrate_ratchets.py` | ラチェットの固定値を下げる道具（§1-3） |
| `scripts/reanchor_mutations.py` | 変異仕様書の pattern を追随させる道具（§1-3） |
| `scripts/sync_guard.py` | 受け側のガード本体。何を守っているかの一覧 |

---

**この文書の表は検査で留めてあります。** `workflow-lint` が
「job N + step N ＝ N 件」の行と、**表の 1 行ずつ**を実物と突き合わせるので、
**実物が動いたのにここが古いままだと CI が落ちます。** 直すのは
`--apply` の 1 回です。

**そして、写さないでください。** 同じ表から `--restore` が入れます（§1-1）——
写す手が無くなれば、写し違いも、写し忘れも無くなります。
