# 検知率向上サマリ 2026-07-20 — ランタイム相関検知の新設と「到達性」ハードニング

このセッションで main にマージした検知強化の集約記録。テーマは2つ:

1. **単発イベントでは原理的に見えない「レート/ファンアウト現象」をステートフルに検知する**（ランタイム・バースト検知器の新設）。
2. **「作ったのに本番で動いていない」サイレント故障を体系的に潰す**（到達性ハードニング）。

稼働サーバ（ネイティブ postgres16 + nats + `go build` した detection）に対し、各検知を **NATS 注入で E2E ライブ実証**済み。

---

## 1. ランタイム・バースト検知器（5種）

実績ある `NetworkScanDetector`(T1046) と同型のステートフル構造（スライディング窓・キー別状態・発火後 dedup・決定的クロック・キー数上限で evict）。**いずれも `matches` に載るため `KillChainScorer` 相関へ自動供給**され、多段侵入の相関検知率も底上げする。

| # | 検知器 | 技術 | 手口（レート現象） | kill-chain 段 | PR |
|---|---|---|---|---|---|
| ⑧ | `discovery.go` | T1033/T1082/T1057/T1016/T1049/T1007/T1069… | 探索コマンドの分類→**単発は無音**でkill-chainに供給＋4種以上のバーストのみ相関1件 | discovery | #483 |
| ⑨ | `auth_attack.go` | T1110 / T1110.003 | ブルートフォース（単一アカウント多数失敗、成功でリセット）＋パスワードスプレー（1ソース→多数アカウント） | credential-access | #486 |
| ⑩ | `file_burst.go` | T1486 | 1プロセスが短時間に多数ファイルを破壊的操作（拡張子・ツール非依存） | impact | #486 |
| ⑪ | `lateral_fanout.go` | T1021 | 1ホストが多数ホストへリモート管理ポート接続（縦=netScanに対し横） | lateral-movement | #486 |
| ⑫ | `exfil_volume.go` | T1048 | 外部宛先への累積送信バイトが閾値超（内部RFC1918は除外） | exfiltration | #488 |

**設計思想**: 単発では管理者/正常挙動と区別できない弱い信号（探索コマンド、単発ログイン失敗、単一ファイル書き込み）を**単独アラート化せず**、レート/相関でのみ判定する。これにより**誤検知を増やさず**に検知率を上げる。

### ライブ実証の実測値（稼働サーバ）
- ランサム: `locker.exe`が30秒で60ファイル → severity 9 / T1486 発火。
- 横展開: 8ホストへSMB → T1021。スプレー: 1ソース→6アカウント → T1110.003。ブルートフォース: 6回失敗 → T1110。
- 持ち出し: 外部へ500MiB → T1048 発火／**同量を内部宛に送っても無音**（`isExternalIP` が除外）。

## 2. サイレント故障の是正（到達性ハードニング）

「検知ロジックは正しいのに、本番のイベントが検知器に届かず一件も発火しない」故障を3件是正。いずれも**ライブ検証やコード監査で初めて露見**するクラスで、テストがグリーンでも本番で死んでいた。

| PR | 故障 | 根因 | 是正 |
|---|---|---|---|
| **#480** | クラウド不審操作アラートが1件も永続化されない | `agent_id` 空文字を uuid 列にバインド→ SQLSTATE 22P02 で無言脱落 | 空なら NULL バインド。回帰テスト追加 |
| **#491** | ランサム検知(⑩)が本番で無反応 | file イベントの action は flat の `operation` キー（`action` は process 専用）なのに `action` を読んでいた | `operation` 優先読み。proto enum 形式の回帰テスト追加 |
| **#492** | 実在フィールドを参照するルールが誤って defer/inert | `SupportedSigmaFields` に `bytes_sent`/`bytes_recv`/`state`/`old_path`/`file_size` が欠落 | 追加＋**emit/supported 同期ガード**テストで再発を自動検出 |

### 到達性監査の方法論（再利用可能）
1. 各検知器が**読む flat フィールド名**を洗い出す。
2. ingestion(`handler.go`)が**実際に emit する flat キー**と突合。
3. 名前不一致（`action`↔`operation`）・欠落（`bytes_sent`）を検出→是正。
4. **同期ガードテスト**（`TestEmittedEventFieldsAreSupported`）で乖離を CI 常時監視。

この「emit と consume の契約」を明示・テスト化したことが、今後の検知器追加でのサイレント死を防ぐ最大の資産。

## 3. 残るギャップ（この環境ではコード完結不可）

`field_support_audit` が inert と判定する残り2件は**真のセンサーギャップ**で、エージェントのテレメトリ拡張が必要（隔離サンドボックスでは完結しない）:

- **LSASS Memory Dump（GrantedAccess）** — Sysmon EID10 相当が必要（credential_access typedFindings で別途カバー済み）。
- **Linux cron ジョブ（file Contents）** — ファイル内容テレメトリが必要（`/etc/cron*` パスルールで別途カバー）。

その他、Windows Security EventID（1102 等）、Kerberos チケット（Kerberoasting）、ブラウザ/クラウド資格情報ファイルの深いアクセス監視なども**センサー側の実装**が前提。

## 4. カバレッジ全体像（2026-07-20 時点）

- **単発 Sigma builtin**: 160ルール／約70技術（inert は 2/160 = センサーギャップのみ）。
- **ランタイム相関**: `KillChainScorer` が discovery / credential-access / impact / lateral-movement / exfiltration / execution / persistence 等の戦術を横断集約し、4戦術到達で高信頼相関アラート。上記5バースト検知器が各戦術の「弱い信号」を供給。
- **ステートフル検知**: netScan(T1046) / dnsAgg(T1071.004) / beacon(C2周期) / auth(T1110) / fileBurst(T1486) / lateral(T1021) / exfil(T1048) / discovery。

商用EDR比較（`docs/competitive/`）の観点では、**「検知は本物だが第三者検証・規模実証が課題」**という自己評価に対し、本セッションは(1)相関検知の面的拡充と(2)サイレント故障の根絶という、地に足のついた品質改善を積み上げた。

## 5. 追撃セッション（同日）— 死んだ配線の復活と既定OFFセンサの有効化

第2章の到達性監査を**双方向**に拡張し（センサは emit するが消費側が無い／消費側は参照するが emit されない）、さらに**実装済みだが既定OFFで死んでいたセンサ**を洗い出して有効化した。詳細は `検知率向上_20260720_死んだ配線の復活と既定センサ有効化.md`。

| A-1 | リムーバブルデバイス検知の配線 | T1091 / T1200 / T1052.001 | emit有・消費側無（promote欠落でサイレント破棄） | #506 | ✅ merged |
| A-2 | 持続的高CPU＝暗号採掘検知 | T1496 | emit有・消費側無（配列でSigma到達不可） | #507 | ✅ merged |
