## 1. ログインと画面構成

### ログイン

ブラウザで `http://localhost:3000` にアクセスし、ログイン画面で認証します。

| 項目 | デフォルト値 |
|------|------------|
| メールアドレス | `admin@example.com` |
| パスワード | `Admin1234!` |

> 初回ログイン後、**プロフィール** → **パスワード変更** から必ずパスワードを変更してください。

### 画面構成

ログイン後、左側のサイドバーから各機能にアクセスできます。サイドバーは折りたたみ可能です（左上のトグルボタン）。

#### トップバー（右上）

| 要素 | 説明 |
|------|------|
| 検索バー | `Ctrl+K` または `⌘K` でグローバル検索を起動 |
| ベルアイコン | 通知センター（未読件数バッジ表示） |
| SYSTEM OK | システムヘルス状態（緑: 正常 / オレンジ: 異常） |
| ユーザーアバター | ログインユーザーの頭文字アイコン。クリックするとメニューが開き、ユーザー名・ロールの確認およびログアウトができます |

> **ログアウト方法**: 右上のユーザーアバター（頭文字の丸いアイコン）をクリック → **ログアウト** を選択してください。

#### サイドバー構成

| セクション | 主な機能 |
|-----------|---------|
| **エグゼクティブ** | 経営層向け全体サマリー |
| **概要** | ダッシュボード、グローバル検索、タイムライン |
| **検知** | アラート、インシデント、検知ルール、相関分析 |
| **エンドポイント** | エンドポイント管理、フォレンジクス、ライブレスポンス |
| **インテリジェンス** | 脅威インテリジェンス、IOC管理、MITRE ATT&CK、サンドボックス |
| **監視** | ネットワーク、クラウド、コンテナ、メール、DNS監視 |
| **対応** | プレイブック、脆弱性管理、コンプライアンス、SOC |
| **アセット** | 資産ライフサイクル、依存関係マップ |
| **計画** | 脅威モデリング |
| **ナレッジ** | ナレッジベース |
| **分析** | レポート、セキュリティスコア、リスク分析 |
| **管理** | 管理者専用設定（adminロールのみ表示） |

## 2. ダッシュボード

> 📍 画面パス: `/`（ログイン後のトップ画面）

ダッシュボードは30秒ごとに自動更新されます。

### 表示内容

#### エンドポイント状況（上段）

| カード | 内容 |
|-------|------|
| 総エンドポイント | 登録済みエンドポイントの総数 |
| オンライン | 現在通信中のエンドポイント数と割合 |
| オフライン | 通信が途絶えているエンドポイント数 |
| 隔離中 | ネットワーク隔離中のエンドポイント数 |

#### アラート状況（中段）

| カード | 内容 |
|-------|------|
| 未対応アラート | ステータスが「オープン」のアラート数 |
| 調査中 | 対応中のアラート数 |
| 本日の検知 | 当日に検知されたアラート数と前日比 |
| クリティカル | 重大度9〜10のアラート数 |

#### イベント推移グラフ

過去24時間のイベント数をグラフで表示します。

#### 最新アラート

直近のアラートを最大5件表示します。クリックで詳細画面へ遷移します。

#### 脅威トップエンドポイント

アラート件数が多い上位エンドポイントを表示します。

## 3. アラート管理

> 📍 画面パス: `/alerts`（一覧）　`/alerts/[id]`（詳細）　`/alerts/triage`（トリアージ）

**概要 → アラート** または **検知 → アラート** からアクセスします。

### アラート一覧

#### フィルタリング

| フィルタ | 説明 |
|---------|------|
| ステータス | open / investigating / resolved / false_positive |
| 重大度 | 1〜10（数値が大きいほど重大） |
| エンドポイント | 特定のエンドポイントに絞り込み |
| 期間 | 日付範囲で絞り込み |

#### 重大度の目安

| 重大度 | レベル | 説明 |
|--------|--------|------|
| 9〜10 | CRITICAL | 即時対応が必要。ランサムウェア、権限昇格等 |
| 7〜8 | HIGH | 優先対応が必要。疑わしいコード実行等 |
| 5〜6 | MEDIUM | 調査が必要。不審な通信、設定変更等 |
| 1〜4 | LOW | 参考情報。低リスクな異常動作等 |

### トリアージ

> 📍 画面パス: `/alerts/triage`

**検知 → トリアージ** から、未対応アラートを優先度順に効率的に処理できます。

### 一括AI分類（バッチ分類）

アラート一覧でチェックボックスを選択し、**一括操作 → AI分類** を実行すると、選択した複数アラートをまとめてAIで自動分類できます。

| 項目 | 説明 |
|------|------|
| 対象 | チェックしたアラート（最大100件） |
| 処理内容 | 各アラートに対しAIが脅威カテゴリ・対応優先度を付与 |
| 所要時間 | 約1〜3分（件数・モデルによる） |
| 結果確認 | 完了後、各アラートの **分類** 列に結果が反映 |

> 大量アラート発生時（インシデント対応時など）に有効です。個別分析より処理速度は速くなりますが、精度は単体分析より低い場合があります。

### アラート詳細

アラートをクリックすると詳細画面が開きます。

#### 表示される情報

- **概要**: アラートタイトル、重大度、ステータス、検知日時
- **対象エンドポイント**: ホスト名、OS、IPアドレス
- **検知ルール**: マッチしたYARA/Sigmaルール
- **MITRE ATT&CK**: 攻撃手法の分類
- **AI分析**: モデルを選択してAI分析を実行（[AI分析機能](#12-ai分析機能) 参照）
- **関連イベント**: 同時刻前後の関連イベントログ
- **調査メモ**: 対応記録・コメントの入力

#### ステータスの変更

| ステータス | 説明 |
|-----------|------|
| `open` | 未対応（新規検知時の初期状態） |
| `investigating` | 調査中 |
| `resolved` | 対応完了 |
| `false_positive` | 誤検知 |

#### 対応アクション

| アクション | 説明 |
|-----------|------|
| **ネットワーク隔離** | エンドポイントのネットワーク接続を遮断 |
| **プロセス終了** | 特定プロセスをリモートで強制終了 |
| **ファイル隔離** | 不審ファイルを安全な領域に移動 |
| **スキャン実行** | エンドポイントで即時スキャンを実行 |

## 5. エンドポイント管理

> 📍 画面パス: `/endpoints`（一覧）　`/endpoints/[id]`（詳細）

**エンドポイント → エンドポイント** からアクセスします。

### エンドポイント一覧

| 項目 | 内容 |
|------|------|
| ホスト名 | エンドポイントのホスト名 |
| OS | Windows / Linux / macOS のアイコンとバージョン |
| ステータス | オンライン / オフライン / 隔離中 / エラー / 非アクティブ（30日以上ハートビートが無いエンドポイント。再び通信を受け取ればオンラインに戻ります） |
| IPアドレス | 検出されたIPアドレス |
| 最終通信 | 最後にハートビートを受信した日時 |
| アラート数 | 未対応アラートの件数 |
| エージェントバージョン | インストールされているエージェントのバージョン |

### エンドポイント詳細

クリックで詳細情報を確認できます。

- **システム情報**: CPU、メモリ、OS詳細
- **アラート履歴**: このエンドポイントのアラート一覧
- **最近のイベント**: プロセス・ファイル・ネットワークイベント
- **実行中プロセス**: 現在稼働中のプロセス一覧

### ライブレスポンス

**エンドポイント → ライブレスポンス** から、エンドポイントへリモートで接続してコマンドを実行できます（analyst ロール以上が必要）。

左パネルの4タブで機能を切り替えます：

| タブ | 内容 |
|------|------|
| **エージェント** | オンラインのエンドポイント一覧。クリックでセッション開始 |
| **セッション** | アクティブなセッション一覧。中断したセッションを再開可能 |
| **テンプレート** | よく使うコマンドのプリセット（プロセス/ネットワーク/ファイル/システム等） |
| **履歴** | 実行済みコマンドと出力の履歴 |

ターミナルでは `Tab` 補完・`↑↓` 履歴・`Ctrl+C` 中断・`Ctrl+L` クリアが利用できます。

### フォレンジクス

**エンドポイント → フォレンジクス** から、エンドポイントのデジタルフォレンジクス調査を実施できます。

- **ネットワークフォレンジクス**: パケットキャプチャ・ネットワーク通信の詳細分析
- **メモリ分析**: メモリダンプからのマルウェア検出

### ソフトウェア管理

**エンドポイント → ソフトウェア管理** から、エンドポイントにインストールされているソフトウェア一覧を確認できます。

**エンドポイント → ソフトウェア変更履歴** では、ソフトウェアのインストール・更新・削除の差分を確認できます。

### エージェント配布

> 📍 画面パス: `/admin/agent-deployment`

**エンドポイント → エージェント配布** から、新しいエンドポイントへのエージェントインストール手順とインストーラーをダウンロードできます。

## 6. 脅威インテリジェンス

> 📍 画面パス: `/threat-intel`（フィード管理・IOC検索・脅威アクター）　`/mitre`（ATT&CK マトリクス）　`/threat-intel/darkweb`（ダークウェブ監視）

### インテリジェンスハブ

> 📍 画面パス: `/threat-intel`

**インテリジェンス → インテリジェンスハブ** では、収集された脅威情報を一元管理します。

### IOC管理

> 📍 画面パス: `/ioc`

> 📍 画面パス: `/mitre`

> 📍 画面パス: `/threat-hunting`（手動ハンティング）　`/threat-hunting/automated`（自動ハンティング）　`/threat-hunting/notebook`（ノートブック）

**インテリジェンス → スレットハンティング** から、仮説ベースの能動的な脅威探索を実施できます。

### マルウェアサンドボックス

> 📍 画面パス: `/malware-analysis`

**インテリジェンス → マルウェアサンドボックス** で、不審ファイルを安全な環境で動的解析できます。

### 脅威アクター・APTトラッカー

> 📍 画面パス: `/threat-intel/actors`（脅威アクター一覧）

既知の脅威グループ・APTグループの情報とTTPsを参照できます。

## 9. 検知ルール管理

> 📍 画面パス: `/rules`（Sigmaルール一覧）　`/yara`（YARAルール管理）　`/suppressions`（アラート抑制）

### ルール一覧

> 📍 画面パス: `/rules`

**検知 → 検知ルール** からアクセスします。

| 項目 | 内容 |
|------|------|
| ルール名 | ルールの名称 |
| タイプ | YARA / Sigma / Behavioral |
| プラットフォーム | 適用OS（Windows / Linux / macOS） |
| 深刻度 | 検知時のアラート重大度 |
| 自動対応 | 隔離・プロセス停止・検疫の自動実行設定 |
| MITRE | 対応するATT&CKテクニックID |
| 有効/無効 | ルールのトグル切替 |

### ルールタイプ

| タイプ | 説明 |
|--------|------|
| **YARA** | ファイル・メモリのバイナリパターンマッチング |
| **Sigma** | ログ・イベントベースの汎用検知ルール |
| **Behavioral** | 機械学習による異常スコアリング |

### ルールの追加方法

#### 手動作成

1. **検知ルール** → **新規ルール**
2. ルールタイプを選択
3. ルール内容を入力
4. テスト実行で過去イベントへの適用をシミュレーション
5. 保存で有効化

#### AIで生成

1. **AIで生成** ボタンをクリック
2. 検知したい脅威の説明を入力（例: 「PowerShellエンコードコマンドの実行」）
3. ルールタイプとプラットフォームを選択
4. **ルールを生成** → 内容を確認して保存

#### インポート

1. **インポート** ボタンをクリック
2. SigmaまたはYARAフォーマットを選択
3. ルール内容を貼り付けて実行

#### SigmaHQ同期

1. **SigmaHQ同期** ボタンをクリック
2. 自動有効化オプションを選択
3. **同期開始** でGitHubから最新ルールを取得

### アラート抑制

> 📍 画面パス: `/suppressions`

**検知 → アラート抑制** から、誤検知が多いルールの通知を一時的に抑制できます。

## 11. 管理者機能

> 管理者機能は **adminロール** のユーザーのみが利用できます。サイドバー下部の **管理** セクションに表示されます。

管理セクションは以下のグループで構成されており、各グループはアコーディオン形式で開閉できます。現在のページに対応するグループは自動的に展開されます。

2. 以下を入力して **作成** を押す

### AIモデルの設定方法

1. **設定** → **AI分析設定** を開く
2. 使用するプロバイダーのタブを選択（Anthropic / OpenAI / Google / Ollama）
3. APIキー（またはOllamaのサーバーURL）を入力
4. 使用するモデルカードをクリックして選択（✓ 使用中 と表示）
5. 画面上部の **変更を保存** をクリック

### アラート詳細でのAI分析

1. アラート一覧から任意のアラートをクリック
2. 右側の **AI Analysis** パネルを確認
3. **AIモデル** ドロップダウンから使用するモデルを選択
4. **AIで分析** ボタンをクリック

分析結果には以下が含まれます：
- 脅威の概要と重大度評価
- 攻撃手法の詳細説明（MITRE ATT&CKマッピング）
- 推奨対応手順
- 誤検知の可能性評価

### AIアシスタント

**管理 → 分析 & インサイト → AIアシスタント** から、3つのモードで利用できます。

#### チャット

セキュリティに関する質問を自由に入力できます。

**質問例**:
- 「このアラートは本当に危険ですか？」
- 「PowerShellエンコードコマンドの攻撃手法を教えてください」
- 「LSASS メモリアクセスの対応手順は？」

#### アラート分析

アラートのJSONデータを貼り付けて詳細分析を実行します。

- 脅威レベル・誤検知確率の評価
- MITRE ATT&CKテクニックのマッピング
- 具体的な対応推奨事項

#### 対応計画

複数のアラートIDを指定して、統合的なインシデント対応計画を生成します。

- 封じ込め（Containment）手順
- 根絶（Eradication）手順
- 復旧（Recovery）手順

### モデルの選択基準

| 状況 | 推奨モデル |
|------|----------|
| 通常の日常運用 | Claude Sonnet 4.6 または GPT-4o mini |
| APT・複雑な攻撃の詳細調査 | Claude Opus 4.6 または OpenAI o1 |
| 大量アラートの一括処理 | Claude Haiku 4.5 または Gemini 2.0 Flash |
| 長期攻撃の全体分析 | Gemini 1.5 Pro |
| インターネット接続なし・機密環境 | Ollama（Llama 3.1 70B） |
| スクリプト・コード解析 | Ollama（CodeLlama 13B） |

### AI分析とルールベース検知の違い

| 項目 | ルールベースのみ | AI分析あり |
|------|----------------|-----------|
| 検知方法 | シグネチャ・Sigmaルールマッチ | 同左（検知自体はルールベース） |
| 脅威評価 | なし | 文脈を考慮した総合評価 |
| 誤検知判定 | なし | 低/中/高で評価 |
| 攻撃チェーン | なし | 攻撃の流れを推論・説明 |
| 対応手順 | 固定テンプレート | アラート内容に応じたカスタム提案 |
| 未知の攻撃 | 検知可能でも文脈なし | 類似パターンから意図を推論 |

## 13. AI自動調査

> **必要な設定**: `OPENAI_API_KEY`（OpenAI gpt-4o）または `ANTHROPIC_API_KEY`（Claude）の環境変数設定が必要です。未設定の場合は自動調査はスキップされ、手動トリガーのみ利用できます。

### 自動調査の仕組み

重大度 **7以上** のアラートが発火すると、バックグラウンドで自動的にAI調査が実行されます。

1. アラートの詳細（タイトル・重大度・MITRE ATT&Kタクティクス）を取得
2. 対象エージェントの直近10分間のイベント（プロセス・ネットワーク・ファイル）を収集
3. 構造化プロンプトを生成してAIに送信
4. 分析結果をアラートレコードに保存

### アラート詳細でAI調査結果を確認

1. **アラート一覧** から重大度7以上のアラートをクリック
2. **AI調査** パネルに以下が表示されます：
   - 調査実行日時・使用モデル
   - 脅威の概要と攻撃チェーンの説明
   - MITRE ATT&CK テクニックマッピング
   - IOC（不正IPアドレス・ドメイン・ファイルハッシュ）
   - 推奨対応手順

### 手動での再調査

```
POST /api/v1/alerts/:id/investigate
```

アラート詳細画面の **再調査** ボタンからも実行できます（最新の関連イベントで再分析）。

## 14. コンプライアンス自動評価

システムは毎日 **02:00 UTC** に全エージェントを対象にコンプライアンス評価を自動実行します。

### 対応フレームワーク

| フレームワーク | コントロール数 | 評価内容 |
|--------------|-------------|---------|
| **CIS Benchmark** | 5 | 資産管理・安全設定・監査ログ・マルウェア防御・NW監視 |
| **NIST CSF** | 5 | 識別・防御・検知・対応・回復の5機能 |
| **SOC2** | 4 | 可用性・機密性・変更管理・インシデント対応 |

### コンプライアンスレポートの確認

**対応 → コンプライアンス** からアクセスします。

#### エージェント別レポート

`GET /api/v1/compliance/agents/:id?framework=cis`

各コントロールの評価結果：
- **pass**: 要件を満たしている
- **fail**: 要件を満たしていない（改善推奨事項あり）
- **unknown**: データ不足で判定不可

#### 組織全体サマリー

`GET /api/v1/compliance/summary`

全エージェントの平均スコアをフレームワーク別に表示します。

#### 手動評価のトリガー

`POST /api/v1/compliance/agents/:id/evaluate?framework=nist`

スケジュールを待たずに即時評価を実行できます。

## 18. 脅威モデリング

**計画 → 脅威モデリング**（または直接 `/threat-modeling`）からアクセスします。

システムアーキテクチャの脅威を図式化・分析するためのビジュアルエディタです。

### キャンバス操作

| 操作 | 方法 |
|------|------|
| 図形の追加 | 左パネルの要素（プロセス・データストア・外部エンティティ等）をクリック |
| 図形の移動 | 図形をクリックしてドラッグ |
| 図形のリサイズ | 図形右下の ◢ ハンドルをドラッグ |
| 図形の選択 | クリックで選択（青枠表示） |
| 図形の削除 | 選択後 **Delete** キー または右パネルの削除ボタン |

### 図形の種類

| 図形 | 用途 |
|------|------|
| プロセス | アプリケーション・サービスの処理 |
| データストア | データベース・ファイルストア |
| 外部エンティティ | ユーザー・外部システム |
| データフロー | 図形間のデータの流れ（矢印） |
| 信頼境界 | セキュリティ境界（点線ボックス） |

### 脅威分析

右パネルで図形を選択すると、その要素に関連する脅威（STRIDE分析）とリスクレベルが表示されます。
