# サーバに無い宛先（読み取り）の内訳

フロントエンドが `apiFetch` で呼んでいる読み取り（GET）のうち、
`server/internal/api` にルートが1本も無いものの一覧です。**117件**あります。

書き込み側の内訳は `docs/サーバに無い宛先の内訳.md` にあります。
両方とも `frontend/tests/lib/server-routes.test.ts` が件数の上限を固定しています。

## この表の一番重要な数字

**117件のうち72件は、書き込みも同じ接頭辞でルートが無い**接頭辞に属します。

これは「フロントとサーバがすれ違っている」ではなく、
**その機能がサーバ側にまるごと存在しない**ことを意味します。
読み取りも書き込みも届く先が無いので、画面は空を表示し、
操作は保存されません。45の接頭辞がこの状態です。

残る45件は読み取りだけが欠けています。こちらは
「一覧は出せないが操作はできる」といった部分的な欠落なので、
足りない1本を足せば済むことがあります。

## 症状

読み取りは 404 になり、多くの画面が `.catch(() => [])` で空配列に
変換しています。運用担当の目には「まだ何も無い」と映ります。
`DataUnavailable` の帯を全ページに入れたので、いまは
「取得できませんでした」と出ますが、**何度更新しても取得できません**。

## すでに直したもの

### 経路の綴り違い（1件）

`GET /admin/uba/anomalies` を呼んでいましたが、サーバにあるのは
`/admin/ueba/anomalies` です。`e` が1文字足りません。

ただし経路だけ直すと、今度は空欄の行が並びます。サーバは
`username` / `anomaly_type` / `score` / `created_at` で返し、画面は
`user` / `type` / `risk_delta` / `timestamp` を読むからです。
対応表を入れて両方直し、`tests/lib/ueba-anomaly-shape.test.ts` で固定しました。

### 計測側の誤り（5件、コードは無変更）

`` `/api/v1/admin/api-security/events${params}` `` のように、末尾の補間で
クエリ文字列を組み立てている呼び出しを、経路の一部として数えていました。
実行時には `/admin/api-security/events` になるので、これらは正常です。
判定を直しました（読み取り 121 → 117）。

## 残り

以下は判断が要ります。読み方は書き込み側と同じ3通りです。

1. **サーバ側を作る** — 機能として必要で、まだ実装されていない
2. **画面を落とす** — 機能として要らない
3. **未実装として明示する** — 作るか落とすか決まるまで、
   `NotImplemented`（501）や `BackendPendingBanner` で誤解だけ消す

- 書き込みも同じ接頭辞でルートが無いもの: **72件 / 45接頭辞**
- 読み取りだけルートが無いもの: **45件 / 34接頭辞**
